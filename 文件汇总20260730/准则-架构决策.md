## 裁判组声明→裁定模式（V5.3.3）
*   **核心原则**：组件只提交声明，裁判统一裁定并执行。组件在整个攻击流程中不再直接修改状态，引擎（裁判组）是唯一的状态写入者。
*   **七个边裁**：行动调度 `resolveActionOrder`（priority/skip/pass 声明收集 + 冲突裁决）、目标选择 `selectAttackTarget`（通用规则 + 组件 targetResult 声明 + 存活校验）、闪避计算 `_dodgeRules` 规则注册表（引擎注册通用规则、精英回合开始注册）、伤害计算 `calcFinalDamage`（breakDef/ignoreDef/bonusDmg/dmgMultiplier 一次性收集统一结算）、伤害免疫 `resolveDamageImmune`（immune 声明收集，任一声明即免疫）、死亡结算 `resolveDeaths`（`_pendingDeath` 标记 → 攻击后效果完成后统一扫描）、攻击后效果 `resolveAfterDamageEffects`（leech/heal/splash/rebound 按固定顺序统一执行）。
*   **死亡判定变更**：所有死亡判定从 `alive = false` 改为 `_pendingDeath = true`，延迟到攻击后效果全部完成后统一结算，避免后续效果操作已死单位。

## 行动裁判（V5.3.1 / V5.3.2）
*   **beforeActionSelect**：引擎选人前发射信号，单位声明 `priority`（谁先动）、`skip`（不在战场，不进候选池）、`pass`（存在但无法攻击，行动后不换阵营）。裁判统一排序，高优先级抢动，skip 不进候选，pass 行动后不换阵营。
*   **isPriorityAction**：高优先级行动（如苦练）或被遮挡/眩晕等单位完成动作后，设此标记为 true，跳过 `currentSide` 切换，不占本队正常回合。
*   **onRoundStart**：回合开始阶段发射，用于精英组件处理苦练 buff、性奋授予、快乐回血、蛛变、玄冥中毒、永久 carry 等逻辑。⚠️ 必须同步执行，引擎后续属性计算依赖这些加成。
*   **onRoundEnd**：回合结束或战斗结束时发射，用于姐姐蝶变飞回、张无忌变身检查、妹妹蛛落等清理逻辑。
*   **beforeFirstAllyAttack**：明教首次攻击前发射，小昭姐组件监听此信号自行处理蝶变附身，替代引擎硬编码调用。
*   **眩晕双拦截**：`processUnitAttack` 入口拦截（眩晕单位拒收任何攻击指令）+ 攻击后拦截（攻击后被眩晕则 `afterAttack` 等后续效果全部跳过）。引擎统一拦截，组件无需各自检查。

## 事件总线（V5.3.0）
*   **统一信号**：`on(event, handler, priority)` / `emit(event, data)`，当前信号清单：`beforeSelectTarget`、`beforeAttack`、`beforeDamageCalc`、`beforeDamageCalcFinal`、`beforeDamageApply`、`afterDamageApplied`、`afterAttack`、`afterMiss`、`allyDamaged`、`beforeActionSelect`、`onRoundStart`、`onRoundEnd`、`beforeFirstAllyAttack`。
*   **注册化**：职业（战士破防/远程成长/防战坚盾）、海克斯效果、精英技能全部改为 EventBus 监听器，核心逻辑不再硬编码。每回合 `eventBus.clearAll()` 后重新注册。
*   **统一出口**：所有组件必须导入 `emitCoreEvent`（或 `emitEvent`），禁止直接访问 `window._emitEvent` / `window._battleEvents`。事件通过 `GlobalStore.pushBattleEvent` 入队，播放器统一消费。

## 引擎与 UI 边界
*   **引擎-UI 解耦**：引擎只算账、写战斗日志；播放器读日志控制 Store 更新时机（动画播完才改 hp/pos/alive）。禁止引擎通过全局变量直接改 UI Store。
*   **倍速双轨并行**：手动锁定倍速与滚动慢放互不覆盖，`slideSpeedActive` 标记慢放中；同一状态只能有一个权威来源，避免两处同名变量各自维护。
*   **battleStore 唯一状态源（V5.7.2；V6.1.1 修订）**：战斗期唯一权威是 battleStore（`modules/24battle-store.js`）——所有读都从 `store.getState().units` 现取，按 uid 查单位统一走 `findUnitByUid`。`c.UI.allyTeam/enemyTeam` 为过渡冗余：仅 IDLE 阶段（开局造队、站位调整）与赛后面板定稿快照使用，战斗期不再回写，store 未就绪时仍被读作兜底（player/42、45、46、49），**新代码禁止读 `c.UI.*`**。snapshot 开局定稿、仅供重新开局重置，不反映战斗进行中状态。（`rebuildUISnapshotFromStore` 已删，本条目按现状重写）
*   **stageAction 三线映射（V5.7.3）**：引擎 factType → 播放器 stageAction → 格子线/特效线/日志线的映射协议与三线节奏原则（格子同步优先、特效异步跟随、日志最慢不阻塞），全表见 `准则-舞台动作映射.md`。
*   **架构终态蓝图（V5.7.13）**：长期目标基准——"加内容=只加数据、不碰引擎代码"的可扩展形态（七条单一化原则 + 扩展通道表 + 四阶段落地路径 + 验收标准），全谱见 `准则-架构终态蓝图.md`。
*   **player→fx 依赖反转（V5.7.5）**：player 层禁止 import fx 层任何函数（含动态 import），只 `eventBus.emit` 携带数据（unit 传引用不传 uid）；信号常量集中在 `infra/55-fx-signals.js`（`FX_SIGNALS`，`fx:` 前缀与战斗信号空间隔离），emit 侧与订阅侧各自 import（X→infra 均合法）；`fx/89fx-subscriber.js` 模块加载即注册、静态 import 87/86/88 转调，不改动特效函数实现。快进判断归位订阅器（表现层职责），await 语义逐一对应原调用点；与 core→render 拆墙对称，新增特效只需加信号 + 订阅行。

## 词条系统（属性只算不存；原协议 6.3 归档）
*   **登记与现算（`core/13battle-shared.js`）**：`addMod(unit, stat, { source, value, ttl, group, op })` 登记词条，`getStat(unit, stat)` 现算终值——公式 `(base + addSum) × (1 + mulSum)`。`ttl: 'permanent' | 'round' | 'attached'`；`op: 'add'`（默认，加法）| `'mul'`（百分比，存 0.3 表示 +30%）。
*   **清理**：`removeModsByTTL(unit, ttl)` / `removeModsByGroup(unit, group)`。
*   **红线**：禁止直改 `unit.atk` / `unit.def` / `unit.maxHp`——一律 `addMod` 后由 `getStat` 现算；maxHp 变更另需 `refreshMaxHp(target, source, reason)` 同步（升则等量加、降则等比降）。

## 三大架构方向（V6.1.0）
*   **特效层与 grid 解耦**：fx 层禁止缓存 cell DOM 引用——grid 每次重绘即重建 DOM，旧引用变游离元素（克隆体极小/残留蓝格子/动画掐断的根因）。cell 获取统一走 `fx/90fx-ref-manager.js`（`getUnitCell` / `getCellByPos` / `snapshotUnitCell` 实时查询或纯坐标快照）；表现型状态（如子弹时间原格隐藏）走 `unit.state._flyMode` + store dispatch 由 renderGrid 分支驱动，不直接改 DOM。
*   **fact 纯数据化**：fact.data 内禁止塞活体 Unit 对象（渲染/翻译层持有模拟层引用会破坏"模拟不可变"边界），一律 `{uid, name, pos}` 纯数据快照（`snapshotUnitForFact`）；渲染层按 uid 从 battleStore 反查（`findUnitSnapshotByUid`）。涉及：attack/miss/dodge、BUFF_SUMMARY、风袭/流星溅射、换位推撞、夺舍交换、张无忌切换、PASS。
*   **播放器瘦身**：`playBattle` 只管播放编排。战报/积分/通关奖励拆 `player/48battle-report.js`（`buildBattleReportData` / `computeVoteResult` / `grantClearRewards`）；buff 选择/飞天方向拆 `player/49battle-flow.js`。积分保护顺序铁律：**先读旧值 → 判保护 → 再写入**（`shouldPersist` 标志由调用方决定是否写 localStorage）。

## 状态变化统一广播 + 单位裁判系统（V6.1.0）
*   **唯一发射口**：9 类状态变化（死亡/换位/飞天/落地/附身/飞回/眩晕/变身/换职业）一律走 `infra/59-state-change.js` 的 `emitStateChange(unit, changeType, extra, log)` 广播 `ON_UNIT_STATE_CHANGE`；禁止只改 state 不发信号、或各处自定义私有信号。日志 fact 字段形态各异，仍由各源头自行 push。
*   **裁判系统**：`core/19unit-watch.js` 的 `watchUnit(unit, checkFn, onChange)`——登记观察条件，布尔翻转即触发回调；注销用 `unwatchUnit` / `unwatchAllForUnit`，每回合 `eventBus.clearAll()` 后必须 `clearAllWatchers()`（每回合 A/B 是克隆，旧登记作废）。
*   **可选性唯一答案**：`canBeTargeted(unit)`（`core/03battle-utils.js`）回答"能否被选中"——存活 + 未标记不可选 + 非飞天/附身；所有依赖可选性的机制以此为准，不再各自散判。
*   **接入形态约束**：接入方（张无忌前排切换、成昆幻影跟随）只允许标准"登记条件 + 回调动作"形态，禁止为个例加特判。张无忌由此删除 3 个信号订阅 + 3 个重复判定 + 回合兜底，覆盖率从 3 源扩到 9 源。

## 精英技能归属原则（V5.3.3）
*   **引擎保留**：通用战场规则——遮挡判定、拒马生成/销毁、属性重置、圣火令行列生成、Buff 统计日志、胜负判定。引擎是裁判，不识别任何具体精英名字。
*   **数据声明（V5.7.0 起）**：特定精英角色的行为逻辑——苦练、性奋/新婚、九阴白骨爪、玄冥联动、成昆幻影、叛逆突袭、混元霹雳劲等——以 `mechanics` 声明写在 `gameData`，由 15 号解释器装配成监听器提交声明，裁判统一裁定；附身/飞天/蛛落、快乐回血等小昭/张无忌专属机制暂留组件内，后续逐步声明化。
*   **空列/残血光环**：加成写入 `_emptyColBonus` 和 `_bloodAuraBonus` 字段，由引擎的攻防汇总公式统一计算，不直接改 `atk`，确保详情弹窗可查来源。

## 既有决策
*   **小昭附身**：转移用 `_baseAtk` 防叠加；飞回血量计死亡队友（总血量/总血上限比例）。
*   **妹妹飞天**：百分比只看当前 `maxHp`，别用 `_baseMaxHp`。触发时机用 `beforeDamageApply` 信号。
*   **玄冥联动**：打完必须 `partner._acted = wasActed`，防吞行动。`_isLinkAttack` 标记防递归。
*   **战报修复**：统计字段走 `SYNC_BATTLE_STATS`，引擎侧直接覆写。
*   **圣火令首回合**：`playBattle` 初始 `battleState` 需深拷贝全量 `activeBuffs`。
*   **苦练优先行动**：通过 `beforeActionSelect` 声明 `priority: 1`，行动后不切换阵营。历史教训：V5.3.1 删除 `kuLianUnit` 后曾漏掉阵营切换判断。
*   **不拆 Unit**（2026-09-21 决策留档）：有建议把 Unit 拆成"引擎态（可序列化纯数据）+ 表现态（渲染层私有）"。**不做**。理由：Unit 上的 FSM（张无忌形态、小昭附身/飞行）是战斗逻辑，不是表现层状态；拆出去等于把战斗逻辑搬到渲染层，与 `modules/27` 定案冲突。联网序列化用 `plainUnit()` 手工剥层解决，不为此重构 Unit。
*   **不引入打包工具**（2026-09-21 决策留档）：有建议上 esbuild 压体积、加快首屏。**不做**。理由：`tools/106` 的 `ALL_PROJECT_FILES` 按路径列文件、`tools/103` 按路径 fetch，整套"复制包发给 AI"链路依赖纯文件结构；打包后该链路断裂，且失去"离线可用、AI 可直接读源文件"两个好处。
