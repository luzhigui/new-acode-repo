## §1 死亡判定改用实数（`ed5221d2`）

**玩家视角现象**：血条还剩一丝（0.x 点）的单位会直接倒下；某些场景反过来「血显示 0 但人还站着」，两侧口径对不上。

**涉及文件与行号**
- `core/212-battle-attack-chain.js` `applyAttackResult()` L336–338
- 显示侧：`render/407-facts-attack.js`、`render/413-generic-renderers.js`、`ui/703-ui-render-5v5-test.js`

**改前 / 改后**
```js
// 改前（core/212 L336）
let hpAfter = Math.floor(target.hp) - hpLoss;
let dead = hpAfter <= 0;

// 改后
let hpAfter = target.hp - hpLoss;
let dead = hpAfter <= 0;
```

**判断依据**
1. 血量在 V5 系列已改为实数累加（`core/214` 的 `getStat` / `applyStatChange` / `refreshMaxHp` 都不再 floor/round），此处若仍 floor，等于在判定点丢弃小数。
2. 判定必须与写回口径一致：`applyStatChange` 写的是实数，判定也该用实数，否则「刚写 0.4，判定读 0」。

**风险与待验**
- 浮点累加误差：0.1 反复加减后可能出现 `1e-16` 级残值，`hpAfter <= 0` 判活 → 需要真机/基线验证「残血击杀」是否稳定。
- 只改了 `applyAttackResult` 一处。其他直接判死的路径（`core/210` 回合结算、`core/213` 边裁、召唤物死亡）是否同口径，未逐一核对。

## §4 唐文亮冲刺血量改由引擎 payload 下发（`f4905cba`）

**玩家视角现象**：唐文亮冲刺时对方血条「空 → 满 → 掉」，同一刀被扣两次，血直接见底（老板实机反馈）。

**根因**（这是本次最重要的架构修正）

- 主动冲刺：公告插在攻击行**之前**，动作执行时 store 还是扣血前的值 → 反推正确。
- 被动冲刺（被打满七层触发）：公告插在攻击行**之后**，攻击组收尾已把真伤害写进 store → 再反推 = 二次扣血。

- `fx/616-tangwenliang-dash.js` L25（文件头口径）、L81 `snapshotHpBefore()`
