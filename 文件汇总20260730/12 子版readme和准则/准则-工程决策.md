// ==================== 一、决策准则（9 条·含本项目口径） ====================

1. 零兼容包袱 —— 照用，且本项目更严
   不留兼容层、迁移脚本、降级兜底，过时逻辑直接删除。
   项目依据：协议 〇·五「允许坏，禁止折中」——为了「当前能跑」而留旧路 = 违规。

2. 极简实现 —— 照用
   只写解决当前问题的最少代码；不预置配置项、开关、未来钩子。
   判据：这行代码是为「已经存在的需求」还是「想象中的需求」？后者删掉。

3. 渐进落地 —— 改写（与本项目有实质冲突）
   通用版「绝不拆毁已有可运行实现」会反噬本项目——架构迁移允许一次性切换、允许中途跑不了；
   但**禁止新旧并存**；回归**默认不跑**——仅当 ① 用户明确要求、或 ② 改动面很大（跨多文件）时才跑（`node --check` + `smoke-headless` + `rules-replay`）后再往下走。

4. 架构长远 —— 照用，落成本项目既有铁律
   交互链路单向：`ui/fx → player → render/modules → core → infra`，禁止反向 import、禁止 window 桥；
   机制走「声明 → 裁定 + 枚举」，属性只算不存（addMod / getStat）。

5. 模块化分离 —— 照用
   纯计算 / 纯判定 / 纯渲染隔离；特效函数只能出现在播放器层，禁止写入 core/。

6. 优先复用 —— 照用，且项目已有明确复用清单
   先查：`infra/56` 枚举、`infra/57`+`core/16` 裁定器、现有 fact / stageAction 原语、`core/13` 公共函数。
   禁止裸字符串、禁止同类逻辑第二份实现（重复实现 = 未来两套口径打架）。

7. 成熟库优先 —— **降权**（本项目唯一明确例外）
   主代码保持零依赖：纯文件结构 + 浏览器原生 ESM，是「离线可玩 + tools/103 复制包发给 AI」两条链路的地基，引 npm 会直接掐断。
   允许范围：仅 `tools/`（构建/脚本）与 `tests/`（开发工具）可用 npm 工具。
   理由：这里的「轮子」不是重复造，而是**刻意不引入**——符合「循证设计」而非违背。

8. 循证设计 —— 照用
   参考成熟游戏的同类机制 + 本项目自己的体检与回放数据（`tests/` 基线/规则），不凭空自创未验证的模式。

9. 工具面向人，不面向 AI —— 新增（2026-09-28）
   给用户用的工具（`tools/` 下的页面）呈现顺序固定为：**一句结论 → 可视化对比 → 原始数据收进折叠区**。
   禁止把路径原文、内部指标（如 medoid 典型度）、A→B / B→A 全量明细直接倒给用户——人看不懂等于没做。
   参数、字段、旋钮一律带**中文说明**（技能名 · 字段名 + 单位换算），英文标识符不得作为唯一标签。
   反面样本：工具 119 / 120 初版。正面样本：文件复制器。
   注：只做给 AI 自己用的临时探针不适用本条（探针不入仓）。

// ==================== 二、执行规范（4 条） ====================

1. 先读后改：改前通读整个受影响函数（函数头到函数尾），不只改那几行——只看局部会漏下游依赖。
2. 先定验收标准：动手前先写判据（体检规则或临时探针，探针不入仓），改后跑三件套：
   `node --check` → `node tests/smoke-headless.mjs 20` → `node tests/rules-replay.mjs`。
3. 运行环境：Windows 10/11 + PowerShell 7。**不支持 `&&` 与 heredoc**——
   命令串联用 `;`，多行 commit message 用 `git commit -F 文件`。
4. 改动量量化：一律报「完整文件数 + 前后对比组数」（如「1 完整文件 + 2 组对比」），禁止「大/中/小」。

// ==================== 三、交互规范（2 条） ====================

1. 不臆测：规则、数值、设计细节不确定 → 先问，不猜；不把用户没要的东西（新角色、实验机制、顺手重构）混进修复里。
2. 更新记忆：重大结论写进 memory——跨项目偏好写 `user_profile.md`，项目约束写 `project_memory.md`。

// ==================== 四、上下文成本（省积分的硬约束） ====================

计费机制（决定了文件该放哪）：
- `.trae/rules/*.md` —— **每轮自动注入**，全文字节都随每轮付费（乘对话轮数）。
- `文件汇总20260730/*.md`、根目录 MD —— **不注入**，只在被 Read 时才付费。

据此三条硬约束：
1. `.trae/rules/` 只放「铁律 + 指针」，越短越省；展开说明、案例、历史一律放本目录。
2. 大文件（`记录-更改履历.md`、`记录-历史履历归档.md`）**永不进 rules**；读它们用 offset/limit 取片段。
3. 一件事用一次 Grep/Read 能定位，就不派 subagent（subagent 会重复读文件，上下文开销成倍）。
