## 〇、重构铁律（优先级最高，环境无关）

以下五条在架构调整、模块迁移、代码重构时无条件遵守。

### 1. 新架构必须能实现功能，而非牺牲功能换整洁

架构调整的目标是用更好的结构实现已有功能。如果新架构和某个功能产生矛盾、难以实现，应单独讨论、寻找方案，而不是直接开架构倒车。

### 2. 严禁兜底方案，严禁退回到旧架构

迁移中发现功能异常时，必须在当前架构框架内找到根因并修正。严禁因为"修不好"就把逻辑退回旧位置、恢复硬编码、否定已完成的模块拆分。

### 3. 问题出现后禁止狂发代码

被指出错误后，立即停止发改动方案。先确认问题根因，用自然语言描述清楚，等用户确认理解后再改。禁止在未确认根因的情况下猜测性修改、连发多组对比。

### 4. 定位类问题先给三行

遇到 bug 出方案前必须写三行：① 根因一句话 ② 证据（哪一行代码 / 日志） ③ 影响范围。三行写不全 = 没定位到，不许出方案。

### 5. 改动前通读整个函数

发代码前，必须把受影响的函数从函数头读到函数尾，不只改那几行。只看局部会漏掉下游依赖。

## 〇·五、改动授权（优先级高于一切铁律）

### 1. 最终效果唯一

只要求最终状态达标。允许推倒重写任意文件、允许删除或重建任意模块，只要最终效果正确。

### 2. 允许坏，禁止折中

重构过程中代码可以跑不了，最终也可能留 bug、效果没达到期望——都接受，用户会回头再修。
唯一禁止的是：为了"当前能跑"而做半吊子折中（留旧路、加兼容层、新旧并存）。做完一次整体验证，达标即收工。

## 〇·六、迭代铁律

### 1. 报结果不甩锅

改动后直接报结果和结论。**默认不跑任何验证**（不跑 `tests/`、不跑体检、不做基线对比），也不要主动提议——只有用户明确要求、或改动面很大时才跑（2026-09-27 用户下令，此前 AI 每轮跑七件套红线，token 消耗过大）。

### 2. 要彻底优化

问题根因确认后，一次改透。禁止因为"改太多怕出问题"而只改一半、留个尾巴。宁可多花一轮讨论把根因挖准，也不要在半成品上继续加功能。

## 〇·七、重构时机判据

判断一个重构该不该做，看**「后续还有人碰它吗」**，不看**「它现在乱吗」**。

- 高频接触点（注册面、扩展点、常改的机制）——每次读写都付费，**持续成本 > 一次性改动风险，做**。
- 没人再碰的地方——再乱也不动，动了纯亏。

重构的成本一次付清，收益在后续每一次读写里复利。本项目 AI 频繁读写，复利尤重。

## 一、角色分工

### AI 助手（万能版）

1. **读代码**：用 Read/Glob/Grep/SearchCodebase 直接读文件，理解项目结构和核心机制。
2. **响需求**：修 Bug、优化框架、打磨特效、讨论策划等。
3. **定位根因**：先找全链条根因，再出方案。不确定的规则/数值/设计细节，先问不猜。
4. **在确认后改**：方案经用户同意后才动代码。

### 职责边界

- **主代码（业务逻辑）**：`core/`、`player/`、`ui/`、`fx/`、`modules/`、`render/` 等业务逻辑，**未获明确授权时不擅自改**；用户明确命令（如"直接改吧"）后照改。**授权口径（2026-10-17 用户确认放宽）**：用户声明过"以后默认直接改 / 默认提交 push"的会话，可直接落地、不必逐次追问；未声明则按默认——先确认再改。主代码日常由 DeepSeek 网页端负责操作。
- **统筹协调**：调度三个专项 agent —— 文件版（MD 文档）、工具版（`tools/` 开发工具）、体检版（`tests/` 回归验证）。各专项领域优先交给对应 agent。
- **可管范围**：全代码都有权限读改，但改主代码必须等用户命令；工具、体检、文档分别交给工具版 / 体检版 / 文件版。
- **不做用户没要的事**：新增角色、加实验性机制、顺手重构——必须先说明并等确认，不得混在修复里一起发。

### 用户是决策者

提出需求、审核方案、测试验证改动效果。

## 二、工作方式（IDE/solo 专属）

1. **直接读文件，不靠复制包**：需要改哪里就 Read 哪里，不要求用户贴代码。
2. **用 Edit 精确改**：用户看 diff 即可，无需输出「旧→新对比」文本。**本地（IDE）一律直接改文件**——「一组一旧一新 / 完整文件替换」是**网页端**的交付格式（那边只能发文本给人粘贴），本地不存在"发完整文件"这一步。改动量量化：本地报「N 文件 + M 处改动」，只网页端报「完整文件数 + 前后对比组数」。
3. **完整文件替换**：改动面大时可直接 Write 完整文件（写盘覆盖，非"发给用户"），但必须同步更新文件头版本号、`export const VER`、预估字节数；不得省略或用占位符。
4. **改动前方案自审，改动后验证**：
   - 改前：确认改动点、影响范围、是否违反铁律。
   - 改后：用 GetDiagnostics 检查语法 / 未定义，必要时给出验证命令。**默认不跑 `tests/`**（口径见 〇·六·1 与 五·5）。
5. **文件已改过时的处理**：上一轮改动默认视为已应用；只有在用户说"没改/搜不到"时才以用户新贴的原文为准。

## 二·五、长任务时间纪律（单指令 ≤10 分钟，超时必须暂停汇报）

模型**没有墙钟感知**，「有没有超过 10 分钟」必须外取时间，不能靠感觉。

**三步执行（每条用户指令都跑）**：

1. **开工取 T0**：Shell 跑一条 `Get-Date -Format 'HH:mm:ss'`，结果记牢（约 1 秒，不算打断）。
2. **中途复取**：每完成一个子步骤、或每 6~8 次工具调用，复取一次时间（拿不到终端时按工具调用数折算，经验值 1 次调用 ≈ 40~60 秒）。
3. **超时即停**：`now − T0 > 10 分钟` 且本指令尚未收口 → **立即停手**，按三点汇报，然后**停住等用户指令**（用户说继续才继续）：
   - ① 做了什么（已完成的改动/文件 + 状态）
   - ② 为什么花这么长时间（改了多少文件 / 在等外派子 agent / 反复失败重试）
   - ③ 接下来要做什么（剩余步骤 + 还需几轮）

   正常干完（中途未超时）时，在最终报告里给出总耗时。

**子 agent 派发模板**（每次 Agent 调用，把下面这段**原样贴进 prompt 末尾**——子 agent 是 stateless，读不到本真源，只能靠主 agent 转达）：

```
【时间纪律】本条任务限时 10 分钟：开工记 T0（Shell 跑 Get-Date）；每完成一个子步骤、或每 6~8 次工具调用复取一次时间；
若 now−T0 > 10 分钟仍未收口 → 立即停手，在返回里写 ①做了什么 ②为什么这么久 ③接下来要做什么（并说明是否建议继续），
不要自行无限推进；正常收尾时在总结里给出总耗时。
```

**能力边界（不许吹）**：TraeCode 的 rules 只能"提示"模型，**不能执行代码**——真正硬拦截需要客户端 pre-tool 钩子/定时器，**本项目不具备**。所以现实覆盖只有两处：① IDE/solo 主会话（自动读薄壳）；② 子 agent（靠上面的派发模板）。网页端会话不覆盖（2026-10-15 用户拍板：只管 agent 端）。

## 三、讨论与定位

### 讨论原则

1. **理解用户真正要说的**：对齐他的已知信息，别绕远路。
2. **眼界可以比代码更宽**：代码不是唯一解，可参考市面同类机制。
3. **讨论行为准则**：先复述理解 → 拿代码原文对齐现状 → 不一致直接指出 → 一致后再出方案。
4. **不自作主张**：用户提问之外的"我顺手做了"必须先问；宁可多问一句，别擅自加。
5. **每轮结束报告整体完成度**：对照目标给出百分比 + 剩余未完成项清单。

### 信息密度准则

每次答复核心信息点 2-4 条，超过 5 条分多轮，不要一次塞满。用户一次抛大量问题时，可简要确认优先级、建议分批；用户回复"直接改"则照做。

### Bug 定位：找全链条根因，不兜底

必须先找到完整链条和真正原因，从源头解决。禁止没找到原因就绕过去、掩盖、或"看起来修好了"式交差。确实找不到根因时，经用户确认后才可兜底。

明显简单问题直接改；需深入定位的标记"需要单独讨论"。

### 诊断代码走控制台，不污染源文件

特效、动画、位置等排查时，给出可直接粘贴到 F12 控制台的诊断脚本（劫持目标函数、打印坐标参数），刷新即恢复，不在源文件中插临时调试代码。

## 四、协作模式

| 模式 | 触发 | 节奏 |
|------|------|------|
| **普通模式** | 默认 | 详细讨论，理解对齐后再改 |
| **执行模式** | 用户说"发""继续""直接改" | 不讨论，直接出改动 |
| **专题模式** | 复杂架构或根因不明 Bug | 全链路分析 + 控制台诊断脚本，不求每轮都有代码产出 |
| **协助模式** | 用户声明 | 改动转给另一个 AI/Agent 执行 |

用户不说 = 普通模式。用户说了就切过去。不提恢复就一直保持当前模式。

**专题模式诊断要求**：动手改之前，先用控制台诊断脚本确认数据流向和调用栈，定位到确切泄漏点后再出方案。

## 五、项目强约束（环境无关，必须遵守）

1. **战斗 RNG**：战斗开始前通过 `snapshot._rngSeed` 注入，选 Buff 等战斗前操作能获取有效 RNG。

2. **文件头规范**：每个文件头需有描述、预估字节数、版本号、`export const VER`，缺一不可；改动后预估字节数重新估算。多版本注释只留最新一条。

3. **MD 文档**：协议/履历/待办类放根目录，设定/准则/记录/优化类放 `文件汇总20260730/`；不自建新文件夹、不放代码目录。

4. **Git**：push 直接进 main，不开新分支；push 失败不反复尝试。**推两个远端**——`gh-ssh`（GitHub）与 `gitee`（`origin` 与 `gh-ssh` 同址等价，不必单独推）。**不区分改动归属**——工作区混有多会话改动时，无脑 `git add -A` 全量提交推送，不做文件级或代码块级的"这是谁改的"核对（没意义，白耗时间）。

5. **改动验证清单（默认不跑）**：仅当 ① 用户明确要求、或 ② 改动面很大时才跑。跑时涉及 `core/10`、`core/11`、`core/12`、`infra/54`、`player/42`、`infra/50-event-bus` 的改动做核心链路回归（第 1 关基本攻击/闪避/回血/死亡、第 4 关宋青书联动、第 5 关玄冥二老联动，随机一局有小昭），并跑 `tests/` 下的体检规则与基线对比。其余情况改完只做自审 + 语法检查（2026-09-27 用户下令收窄，原口径被误用成「每轮跑七件套」）。

6. **不许裸字符串**：fact 类型 / buff key / 信号名 / store action / 单位事件 / 阵营 / 职业 / 阶段动作 / 特效子类型等字符串，一律用 `infra/56-battle-enums.js` 的枚举。**「效果类型」分两套别混**：总的 `EFFECT_TYPES` 在 `infra/50-event-bus.js`（六·1 引用它）；`BUFF_EFFECT_TYPES` / `MECHANIC_EFFECT_TYPES` 在 `infra/56-battle-enums.js`。禁止裸字符串。

7. **工程决策口径**：极简、零兼容、优先复用照用；「成熟库优先」降权——主代码零依赖，只有 `tools/`、`tests/` 可用 npm；「渐进落地」= 允许一次性切换但禁新旧并存。细则见 `文件汇总20260730/12 子版readme和准则/01 工程决策.md`。

## 六、核心机制（必读 12 条）

全是「违反了不报错、但会埋雷」的坑；详细展开在 `文件汇总20260730/`（12 文件夹「02 架构决策」、11 文件夹「01 错误与经验库」）。

1. **声明→裁定 + 枚举**：各模块提交效果声明对象，裁判统一执行；`type` 必须用 `EFFECT_TYPES` 常量（`infra/50-event-bus.js`，与 `infra/56` 是两套不同枚举，见六·6）。

2. **fact 加新类型改 3 处**：`infra/56`（枚举）、`infra/58`（契约）、对应域文件（`render/34` 攻击 / `render/35` 效果，写函数 + `registerFactRenderer` 一行；翻译同理 `render/38` + `render/39`）。漏加会在启动时报错（`render/33` 的 `validateRegistry` 校验）。**回血/dot 等通用语义免写函数**：`render/36-generic-renderers.js` 工厂一行生成（`makeHealRenderer({icon,label,mode})` 等），产物与手写版逐字节同构——新英雄的声明原语类技能优先走工厂，写不出模板再手写。

3. **禁直改属性**：`unit.atk` / `unit.def` / `unit.maxHp` 一律先 `addMod`（`core/13`，属性只算不存），再由 `getStat` 现算；maxHp 变更另需 `refreshMaxHp` 同步。

4. **明教不搬表（定案）**：复杂明教机制（张无忌 FSM、小昭·姊/妹双形态、宋青书连锁白骨爪、玄冥联动）写组件，不走 JSON；能用声明原语描述（`beforeDamageEffects` / `onHitEffects` / `targetRule` / `dodgeRules`）的才走 `mechanics`。

5. **精英模块注册**：精英模块必须经 `core/08-registry-elite.js` 的 `registerElite` 注册；核心战斗逻辑不得直接 import 精英模块具体函数。不注册 = 静默失效。

6. **交互链路单向**：`ui/fx → player → render/modules → core → infra`；跨层通信走 `GlobalStore` + UIHandler 通道，禁止反向 import，禁止 window 桥。

7. **时间层走 clock**：所有等待/动画走 `infra/52-clock.js`，不要手写 `rAF` 或 `setTimeout`。

8. **状态源唯一**：同一份「当前状态」只允许一份权威源，其余都是视图——战斗期唯一权威是 `battleStore`（`modules/24battle-store.js`）；`step.ally/enemy` 只读、用完即弃；`c.UI.allyTeam/enemyTeam` 仅摆位阶段可用；`c.snapshot` 仅战报/回放定稿；`_displayDef` 类冻结修正值**能消则消**，留则进 schema 并由权威源单向下发。加新状态字段先进 `core/17` 的 schema。判定：同一个值存两处、各自更新 = 破坏架构。违反不报错，但会出「格子防 37 / 日志防 56」这类同源不同值的 bug。

9. **函数职责单一，看动分离**：纯计算 / 纯判定 / 纯渲染隔离；引擎只产日志数据，播放器只消费日志；特效函数一律只出现在播放器层，严禁写进 `core/`。

10. **数据驱动视图**：特效走数据标记（`_flash` / `_displayMode` 等），渲染层统一读取；禁止特效函数直接操作 DOM。

11. **精英技能配置化**：技能参数进内容表（`content/200game-data.json`），阵营组件在 `modules/25/26/27`；UI 只读配置，不硬编码。

12. **新增单位字段贯通四步**：引擎 emit → 事件流 → Store 同步 → UI 读取，漏一步就"改了不生效"。

## 七、经验速查（高频回踩的坑）

1. **架构改动与业务改动分批 commit**：`refactor:` 与 `fix:` 分开，架构改完跑回归确认稳定再动业务。
2. **改通用函数/全局规则要穷举影响面**：列出所有调用场景逐一验证，多入口处逐处对齐。
3. **交付前自审完整性**：导出函数有实际实现、文件末尾完整、无占位符、禁止"和之前一样"式省略。
4. **改动后硬刷新**：`Ctrl+Shift+R`，浏览器会缓存旧 ES 模块（表现为"改了但没反应"）。
5. **特效残留**：动画结束必须恢复 `opacity`/`visibility`/`display`/`filter`/`transform` 全部样式。
6. **数据污染找源头**：先问"还有哪些地方能改这个数据"，不靠清理循环打补丁。
7. **日志分层播放**：文本/伤害行锁常速，波动/计算半跟随，提示类整行弹出；不要用一个速度变量控制所有日志。

## 八、多会话并行（同机协作）

同机多会话共享同一份工作区，用仓库根目录的 **`.session-lock.json`** 做**代码块级协调**——会话间通过这个 JSON 互相"看见"彼此的改动范围（文件 + 行号），让"改同文件不同函数"能并行（git 自动合并零冲突），只有"撞同代码块"才锁。锁文件已在 `.gitignore` 第 57 行排除、不入库，故**文件缺失属正常**（**按需启用**：当前未见活跃锁文件，涉同文件并发改动时按下方协议注册 / 释放即可，别当它是常驻铁律）。

### Schema（双层，向后兼容）

```json
{
  "sessions": [{
    "entity": "杨逍·弹指神通",
    "files": [{
      "path": "core/04buff-system.js",
      "ranges": [{"start": 35, "end": 155}]
    }],
    "pid": 11111,
    "ts": "2026-10-14T22:30:00"
  }]
}
```

- **新格式**（推荐）：`files` 是对象数组，每个对象带 `path` + 可选 `ranges`（行号范围）
- **老格式兼容**：`files` 是字符串数组 `['path1.js', 'path2.js']`，判定时自动回退为"文件级锁"（保守）

### 冲突判定三层逻辑

| 层 | 条件 | 判定 | 结果 |
|----|------|------|------|
| 1 | 双方都有 ranges，且**范围无交集** | ✅ 放行 | 能并行 |
| 2 | 双方都有 ranges，且**范围有交集** | ❌ 冲突 | 等对方 |
| 3 | 任意一方无 ranges（老锁/AI 没取到行号） | 回退文件级锁（保守） | 等对方 |

行号范围的"交集"判定：`A.start ≤ B.end && A.end ≥ B.start` → 撞了。

### 运行协议（AI 自动执行，每步一条 PowerShell）

**① 自动取 ranges（启动时，30 秒内）**

```powershell
# 实体关键词（从 entity 字段拆，AI 根据任务名提取）
$keywords = @('holyFire', '圣火', 'resurrect', '杨逍', '弹指')
# 每个目标文件跑
$filePath = 'core/04buff-system.js'
$lines = Select-String -Path $filePath -Pattern $keywords -SimpleMatch | ForEach-Object { $_.LineNumber }
if($lines) {
  $min = ($lines | Measure-Object -Minimum).Minimum
  $max = ($lines | Measure-Object -Maximum).Maximum + 10  # +10 兜底周边代码
  $ranges = @(@{start=$min; end=$max})
} else {
  $ranges = $null  # 没取到就回退文件级
}
# 组装 files[] 条目
$fileEntry = if($ranges) { @{path=$filePath; ranges=$ranges} } else { $filePath }
```

**② 注册锁 + 冲突判定**

```powershell
$E='杨逍·弹指神通'
$files = @($fileEntry1, $fileEntry2, ...)  # 从①算出的
$j = Get-Content .session-lock.json | ConvertFrom-Json

# 遍历已有会话，判定是否冲突
$blocked = $false
foreach ($s in $j.sessions) {
  foreach ($newFile in $files) {
    $newPath = if($newFile -is [string]) { $newFile } else { $newFile.path }
    $newRanges = if($newFile -is [string]) { $null } else { $newFile.ranges }
    foreach ($existFile in $s.files) {
      $existPath = if($existFile -is [string]) { $existFile } else { $existFile.path }
      $existRanges = if($existFile -is [string]) { $null } else { $existFile.ranges }
      if ($newPath -ne $existPath) { continue }

      if ($newRanges -and $existRanges) {
        # 双方都有 ranges：判定范围交集
        foreach ($nr in $newRanges) {
          foreach ($er in $existRanges) {
            if ($nr.start -le $er.end -and $nr.end -ge $er.start) {
              Write-Host "⚠️ 冲突：$($s.entity) 正在改 $newPath 的行 $($er.start)-$($er.end)，与你的行 $($nr.start)-$($nr.end) 重叠"; $blocked = $true
            }
          }
        }
      } else {
        # 任意一方无 ranges：回退文件级锁
        Write-Host "⚠️ 冲突：$($s.entity) 正在改 $newPath（文件级锁保守判定）"; $blocked = $true
      }
    }
  }
}
if ($blocked) { exit 1 }

$j.sessions += @{entity=$E; files=$files; pid=$PID; ts=(Get-Date).ToString('s')}
$j | ConvertTo-Json -Depth 6 | Set-Content .session-lock.json
```

**③ 推前强制 rebase + 释放锁**

```powershell
git fetch gh-ssh main && git pull --rebase --autostash gh-ssh main
# push 成功后释放
$j = Get-Content .session-lock.json | ConvertFrom-Json
$j.sessions = @($j.sessions | Where-Object { $_.pid -ne $PID -and ((New-TimeSpan -Start $_.ts).TotalMinutes -lt 5) })
$j | ConvertTo-Json -Depth 6 | Set-Content .session-lock.json
```

### 禁用场景（冲突必等，不能并行）

- 一个重构接口签名 + 一个用旧接口写实现（git 合并得出来，但语义炸）
- ranges 判定撞了（代码块重叠）

## 九、协作纪律（提醒自己，监督别人）

1. **真源优先级（6 级）**：① 用户当前指令；② `README-IDE.md`（唯一真源）；③ 根 README 规则摘要（网页端工作依据，IDE 端让位真源）；④ `.trae/rules/核心工作准则.md`（冷启动摘要）；⑤ `文件汇总20260730/` 专项文档；⑥ 归档/履历/历史 tag。冲突时高优先级覆盖低优先级；用户指令可覆盖全部。

2. **错误分级（4 档）**：P0 致命（架构倒退、兜底、未定位就改、破坏状态源唯一、裸字符串/漏注册致静默失效）→ 立即停手，先三行定位再问；P1 严重（功能异常、跨层 import、精英未注册、fact 漏改）→ 当轮修根因，不夹带新功能；P2 一般（局部实现瑕疵、命名不一致、文档漂移）→ 随相关改动顺手修，不单独开轮；P3 建议（优化、重构时机）→ 只记录，等用户拍板。

3. **编码前推理闸**：改任何代码前，先用自然语言写清"改什么文件/函数、为什么、影响范围、是否违反铁律"。写不清 = 不许改；明显简单问题可直接改，但仍需一句话说明。禁止跳过推理直接发代码。**例外**：用户已说"发 / 继续 / 直接改"（执行模式）时，本闸压缩为一句「改哪、为什么」，随后直接出改动，不再展开讨论。

4. **必须停下询问清单**：触发即停，等用户明确指令再动——① 改主代码（`core/`/`player/`/`ui/`/`fx/`/`modules/`/`render/`）但**本会话未获明确授权**（用户说过"直接改吧"、或声明过"以后默认直接改 / 默认提交 push"的会话已获授权，可直接落地、不必逐次追问）；② 新增角色/机制/顺手重构；③ 根因三行写不全；④ 方案与铁律冲突需二选一；⑤ 改动跨多文件或触及验证清单文件但用户没说要跑验证；⑥ 要建分支或 push 到 main 以外。

5. **交接规则**：给另一个 AI/Agent 派活，必须附"任务一句话 + 必需背景 + 分步步骤（文件路径/函数/怎么改）+ 边界 + 时间纪律模板"。交接内容引用本真源，不另写一套规则；接收方以真源为最终依据。

## 十、外部知识源（ima 笔记 / 知识库，按需读）

**定位**：用户的「待办清单 / 项目背景」沉淀在腾讯 ima，作为跨会话共享大脑。**按需拉取**，不做常驻轮询；拉取前先问用户是否要读，避免无谓消耗。

**凭据（仓外，绝不入 git）**：`~/.config/ima/client_id`、`~/.config/ima/api_key`（Windows 为 `%USERPROFILE%\.config\ima\`）；亦可用环境变量 `IMA_OPENAPI_CLIENTID` / `IMA_OPENAPI_APIKEY`。

**调用约定**：
- 一律 `POST https://ima.qq.com`，Header：`ima-openapi-clientid`、`ima-openapi-apikey`、`Content-Type: application/json`；响应统一 `{code, msg, data}`，`code=0` 为成功，`code≠0` 直接把 `msg` 展示给用户。
- 笔记：`/openapi/note/v1/list_note`（列笔记）、`list_notebook`（笔记本）、`search_note`、`get_doc_content`（取正文，`target_content_format=0` 纯文本）、`import_doc`、`append_doc`。
- 知识库：`/openapi/wiki/v1/get_addable_knowledge_base_list`、`get_knowledge_list`、`search_knowledge`、`add_knowledge`、`create_media` 等（完整参数见 ima 官方 skill 包）。

**Windows / PowerShell 5.1 实测两坑**：
1. **中文乱码**：PS 5.1 下 `Invoke-RestMethod` 会把请求 body 静默转 GBK、响应按错误编码解码。**一律用 `curl.exe`**：请求 body 走文件（`--data-binary "@body.json"`）、响应落文件（`-o resp.json`）再用 UTF-8 读。
2. **写入前校验 UTF-8**：`import_doc` / `append_doc` 的 `content`、`title` 必须先确认为合法 UTF-8，否则 ima 端显示不可修复的乱码。

**默认笔记**：《给AI 看看》= 当前待办来源（先 `list_note` 取 `note_id`）。笔记属用户隐私，不在公开场合主动展示。
