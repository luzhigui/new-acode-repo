## 二、强制规则

1. **只碰 MD 文档**：不修改 `core/`、`player/`、`ui/`、`fx/`、`modules/`、`tools/`、`tests/` 下的任何代码文件。
2. **MD 存放位置**：
   - 项目协议、履历、待办类 MD → 放**根目录**
   - 设定、准则、记录、实验、优化等文档 → 放 `文件汇总20260730/`
   - 不自建新文件夹
3. **不删业务代码**：清理时只删 MD 相关的临时文件，绝不删 `.js`/`.html`/`.cjs`/`.json` 业务文件。
4. **文件名规范**：文件名不带空格；新增 MD 用中文语义命名，不撞号。
5. **真源索引引用**：任何 MD 提到协作规则（重构铁律 / 协作纪律 / 核心机制 / 项目强约束等）时，**必须引用真源**——写清 `文件汇总20260730/12 子版readme和准则/README-IDE.md` + 章节号，**禁止复制正文另行维护一份**；发现副本与真源漂移，以真源为准修正副本。唯一例外是三个**显式标注身份**的分发件：根 `README.md`（网页端分发副本）、`.trae/rules/核心工作准则.md`（冷启动薄壳）、各 `README-*`（专项衍生协议）。
6. **失效文档归档标注**：文档失效或被取代时**不删正文**，在文件头加一行 `> ⚠ 本文件已失效，由 \`<取代者路径>\` 取代，仅供考古`，并同步第四节清单与真源索引；过时的重名副本一律按此处理。

## 三、工作方式

1. 用 Glob/Read 定位 MD 文档 → 用 Edit/Write 精确改。
2. 改动后检查：内容完整、格式统一（Markdown 语法、标题层级）。
3. 汇报时给出：改动文件清单 + 改动要点。
4. **改完做一致性自检**：全文搜一遍「副本正文是否与真源冲突」「是否有指向已失效文件的死链」，命中即按二·5 / 二·6 修正。
