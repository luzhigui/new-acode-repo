## 二、强制规则

1. **只碰 MD 文档**：不修改 `core/`、`player/`、`ui/`、`fx/`、`modules/`、`tools/`、`tests/` 下的任何代码文件。
2. **MD 存放位置**：
   - **协议 / 准则类** → 放 `文件汇总20260730/12 协议与准则/`（IDE 协议族 05/09/10 + 网页端副本 04 + 各专项协议 06/07/08）
   - **履历 / 待办类** → 放**根目录**
   - **设定 / 记录 / 优化 / 资产类** → 放 `文件汇总20260730/` 对应子文件夹
   - 不自建新文件夹
3. **不删业务代码**：清理时只删 MD 相关的临时文件，绝不删 `.js`/`.html`/`.cjs`/`.json` 业务文件。
4. **文件名规范**：文件名不带空格；新增 MD 用中文语义命名，不撞号。
5. **真源索引引用**：任何 MD 提到协作规则（重构铁律 / 协作纪律 / 核心机制 / 项目强约束等）时，**必须引用真源**——写清 `文件汇总20260730/12 协议与准则/05 IDE协议.md`（架构类引 `09 架构铁律12条.md`、并发类引 `10 多会话并行协议.md`）+ 章节号，**禁止复制正文另行维护一份**；发现副本与真源漂移，以真源为准修正副本。唯一例外是三类**显式标注身份**的分发件：`04 网页端协议.md`（网页端自包含副本）、根 `README.md`（人类门面）、`.trae/rules/核心工作准则.md`（冷启动薄壳）。
6. **失效文档归档标注**：文档失效或被取代时**不删正文**，在文件头加一行 `> ⚠ 本文件已失效，由 \`<取代者路径>\` 取代，仅供考古`，并同步第四节清单；过时的重名副本一律按此处理。

## 三、工作方式

1. 用 Glob/Read 定位 MD 文档 → 用 Edit/Write 精确改。
2. 改动后检查：内容完整、格式统一（Markdown 语法、标题层级）。
3. **改完做一致性自检**：全文搜一遍「副本正文是否与真源冲突」「是否有指向已失效文件的死链」，命中即按二·5 / 二·6 修正。
4. 汇报时给出：改动文件清单 + 改动要点 + 自检结果。
