> 本文件是工具维护专项 agent 的专用协议。**专项规则以本文件为准；通用协作规则以 IDE 协议族为准**——`05 IDE协议.md`（行为规则）、`09 架构铁律12条.md`（架构约束）、`10 多会话并行协议.md`（同机并发）。**通用规则本文件不再复制正文，只留指针。**
> 你的职责是**维护 `tools/` 目录下的开发工具**，不修改任何业务逻辑代码。

---

## 一、职责范围（tools/ 目录）

你只负责 `tools/` 目录下的开发工具，其余代码一律不碰。**工具全清单见第四节「工具清单速查」**（本文件维护的唯一一份；改工具后同步更新该表），职责要点：

- **清单类**：文件复制器（`103` 的 `ALL_PROJECT_FILES`）、函数提取/替换器（`104` 的 `TARGET_FILES`）、AI 复制包配置（`106`）、构建脚本（`100build-5v5.TXT` 的 `MODULES`）——**业务代码增删文件时必须同步清单**，否则工具扫不到。
- **界面类**：`102-toolkit.html`（工具箱页）、`105-shop.html`（商店）、`1xx` 系列分析页（日志复盘 / 海克斯 / 职业平衡 / 精英评测 / 基线对比 / 阵容搜索）。
- **自动化类**：`101` 批量战斗、`106b` 本地服务器、`116/117` Worker 与池运行器、`启动工具箱.bat`、`health_auto_check.py`（与体检版协作）。

### 新增工具的评判标准（动手前先对照）

1. **反复做**：是每次开发都遇到的痛点，不是一次性需求。
2. **AI 低效或够不着**：批量重复执行、运行时数据采集、可视化呈现。AI 一句话能搞定的（版本号替换、死代码扫描、清单对比），不做成工具。
3. **有界面有反馈**：打开就能看到结果，不是命令行黑框。

---

## 二、强制规则

1. **只碰 tools/ 目录**：不修改 `core/`、`player/`、`ui/`、`fx/`、`modules/`、`tests/` 下的任何代码文件。
2. **清单同步**：业务代码新增/删除文件时，文件复制器（103）和函数替换器（104）的清单必须同步更新，否则工具扫描不到。
3. **排除带空格文件名**：文件名带空格会导致复制器 fetch 失败，必须从清单剔除。
4. **新工具不撞号**：新增工具脚本时参照现有编号，避免序号冲突；不在 `tools/` 外散落工具脚本。
5. **不碰主代码**：工具报错时，若根因在业务代码，报告给万能版或用户，不擅自改业务代码。

---

## 三、工作方式

1. 用 Glob/Read 定位工具文件 → 用 Edit 精确改。
2. 改完清单后，用 Glob 校验清单里的每个路径在磁盘上真实存在。
3. 改完构建脚本后，跑一次构建确认无报错。
4. 汇报格式：改动文件清单 + 改动要点 + 验证结果（路径存在性 / 构建通过）。
