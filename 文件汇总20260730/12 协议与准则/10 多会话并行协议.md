## 一、机制与锁文件

同机多会话共享同一份工作区，用**仓库根目录**的 `.session-lock.json` 做**代码块级协调**——会话间通过这个 JSON 互相"看见"彼此的改动范围（文件 + 行号），让"改同文件不同函数"能并行（git 自动合并零冲突），只有"撞同代码块"才锁。

锁文件已在 `.gitignore` 第 57 行排除、不入库。

### Schema（双层，向后兼容）

```json
{
  "sessions": [{
    "entity": "杨逍·弹指神通",
    "files": [{
      "path": "core/04buff-system.js",
      "ranges": [{"start": 35, "end": 155}]
    }],
    "pid": 11111,
    "ts": "2026-10-14T22:30:00"
  }]
}
```

- **新格式**（推荐）：`files` 是对象数组，每个对象带 `path` + 可选 `ranges`（行号范围）
- **老格式兼容**：`files` 是字符串数组 `['path1.js', 'path2.js']`，判定时自动回退为"文件级锁"（保守）

## 二、冲突判定三层逻辑

| 层 | 条件 | 判定 | 结果 |
|----|------|------|------|
| 1 | 双方都有 ranges，且**范围无交集** | ✅ 放行 | 能并行 |
| 2 | 双方都有 ranges，且**范围有交集** | ❌ 冲突 | 等对方 |
| 3 | 任意一方无 ranges（老锁/AI 没取到行号） | 回退文件级锁（保守） | 等对方 |

行号范围的"交集"判定：`A.start ≤ B.end && A.end ≥ B.start` → 撞了。

---

## 三、运行协议（AI 自动执行）

三步，每步一条 PowerShell，可执行代码见 `多会话锁.ps1`：

1. **① 自动取 ranges（启动时，30 秒内）**：按实体关键词（从 `entity` 字段拆）在每个目标文件里 `Select-String` 取行号，取 min/max（max +10 兜底周边代码）作为 ranges；取不到就留空（回退文件级）。
2. **② 注册锁 + 冲突判定**：遍历已有会话逐文件比对——双方都有 ranges 时判范围交集，**有交集即写冲突提示并 `exit 1`**；任一方无 ranges 则按文件级保守判冲突。放行后把自己的 `{entity, files, pid, ts}` 追加进 `sessions` 并写回。
3. **③ 推前强制 rebase + 释放锁**：`git fetch gh-ssh main && git pull --rebase --autostash gh-ssh main`；push 成功后从 `sessions` 里摘掉自己的 pid（并顺带清理 `ts` 超过 5 分钟的陈旧条目）。

**冲突时不许硬上**：等对方释放锁后再继续。

## 四、禁用场景（冲突必等，不能并行）

- 两会话都改 `infra/*` 事件名/枚举/契约（下游一堆依赖）
- 一个重构接口签名 + 一个用旧接口写实现（git 合并得出来，但语义炸）
- ranges 判定撞了（代码块重叠）
