## 一、解决什么问题

网页端 AI 拿不到本机文件，取代码有两条路：

| 方式 | 通道 | 一次能喂多少 | 体感 |
|---|---|---|---|
| **复制包** | .txt 附件卡 | 全量（主代码约 282 万字符） | 记得牢，但要重发、要分包 |
| **URL 直读** | 联网抓取（raw / jsDelivr） | 单文件（约 9 万字符内） | 随时读最新，但一轮一页、堆多会被挤掉 |

**两者都不完美**：复制包 282 万字符 ≈ 88 万 tokens，远超窗口（约 12.8 万），站点靠压缩摘要常驻；URL 直读则是零散片段落在聊天记录里，轮次一多就被压缩挤掉。

**索引模式 = 取两者之长**：发一份 7 万字以内的「代码地图」让它常驻（不被挤掉），需要细节时按地图里的 URL 模板现抓原文（永远最新）。

## 二、索引是什么 / 不是什么

- **是**：地图。每文件的路径、VER、行数、职责一句话、导出符号、依赖、被引用次数，外加分层说明、地基榜、枚举真源清单、URL 模板。
- **不是**：代码。它不可能替代原文——**任何改动前必须按 URL 读原文**，禁止凭索引里的摘写改代码。
- **不是**：协议。协议讲规矩（怎么回执、怎么出清单、不许用行号锚定），索引讲坐标（代码在哪）。两者配合：索引里写「怎么用」，`04 网页端协议.md` 里写「怎么干」。

## 三、标准流程（6 步）

```powershell
$SK   = "C:\Users\luzhigui\.trae-cn\skills\deepseek-web-url-reader"
$REPO = "<仓库绝对路径>"
$SHA  = git -C $REPO rev-parse HEAD

node "$SK\mkbrief.mjs" --repo $REPO --sha $SHA --out "<输出目录>" --desc "$SK\brief-desc.json"   # ① 生成索引（--desc 必须带）
node "$SK\new-chat.mjs"                                                                          # ② 新会话
node "$SK\send-one.mjs" --file "<输出目录>\brief.txt"                                            # ③ 发索引
# ④ 发任务消息（短消息，工业化时走下方模板）
node "$SK\rename-pin.mjs" --new "1023 光明顶索引已读"                                            # ⑤ 改名置顶（别漏）
node "$SK\grab-reply.mjs" "<输出目录>\reply.txt"                                                 # ⑥ 取回复落盘
```

**任务消息模板**：

```
任务关键词：唐文亮 / 七伤拳 / 冲刺 / 回春
按索引挑出相关文件，用索引第 2 节的 URL 模板抓原文，先回执（路径 | VER | 原文片段）再出「旧→新」清单。
用原文片段锚定，不要写行号。
```

**第 ⑤ 步别漏**：2026-10-23 实跑漏过一次，会话停在站点自动名且未置顶，事后难找回。

## 四、硬约束

1. **链接必须带 commit SHA**，禁用 `main`：main 会变，网页端读到的和本地落盘时对不上，清单就废。
2. **索引随每次 push 重建**：SHA 变了旧链接就指向旧代码。`--desc` 不带则 231 条人工职责全丢。
3. **清单唯一真源** = 仓库 `tools/106-ai-pack-config.js` 的 `ALL_PROJECT_FILES`，与复制包同源；漏登等于索引缺文件（2026-10-23 就漏过 `fx/94`，网页端读它 404）。
4. **回执三件套**（路径 | VER 原值 | 原文片段）缺一视为没读到。模型很容易"说读过了"，唯一硬证据是它引出只有原文里才有的字。
5. **锚定用片段、不用行号**：实测它会自报「48 行」（实际 97 行），行号/总行数一律不可信。

## 五、2026-10-23 实机验证记录

| 检查项 | 结果 |
|---|---|
| 单文件完整性（`core/07`，97 行） | 末两行逐字正确、`registerTargetStrategy(` 计数 5（实际 5）→ **内容完整** |
| 自报行数 | 说 48 行（实际 97）→ **行号不可信** |
| 引用真实性（4 处片段 grep 复核） | 全部命中真实原文 → **没有编造** |
| 自查诚实度 | 主动报「fx/94 404 需补读」→ 由此查出 106 清单漏登真缺口 |

**结论**：URL 直读在「单文件精读 + 自查诚实」上达标；不能替代全量常驻，故配索引。

## 七、与复制包模式怎么选

| 场景 | 用哪个 |
|---|---|
| 首次全量交底、需要它通读全部主代码 | 复制包 |
| 日常改一处、查最新版、核对某文件 | 索引 + URL |
| 刚 push 完、要它看最新代码 | 索引 + URL（重建后） |
| 它说"读不到某文件" | 先查 106 清单是否漏登 |
