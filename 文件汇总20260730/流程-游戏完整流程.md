# 光明顶 5v5 完整标准流程

---

## 一、入口与启动

1. 玩家打开 `index.html`（开发集成入口），点击「主游戏」或「小昭·姊/妹」等按钮
2. 浏览器打开 `mode-5v5-test.html`，显示封面页
3. 封面页加载所有 JS 模块，右下角显示版本号
4. 玩家点击「开始游戏」，封面消失，进入主界面

**状态**：`IDLE`，显示初始阵容

---

## 二、阵容生成（`doInitBattle`）

1. 根据当前关卡（1-6），生成我方 5 人阵容
   - 精英按概率出场：张无忌 40%、韦一笑 30%、小昭 30%
   - 若全未出，强制补一个精英
   - 按战力预算分配剩余坑位
2. 生成敌方阵容
   - 前两关纯普通单位
   - 第 3-6 关按 `ENEMY_SQUADS` 配置固定精英出场
3. 双方按站位模板分配位置
   - 张无忌固定 5 号位，韦一笑 6，小昭 4
4. 阵容渲染到九宫格，日志输出「初始阵容」

**状态**：`IDLE`

---

## 三、战前准备

1. 若自动模式为「手动」，玩家点击「调整站位」，可交换我方单位位置
2. 玩家点击「开始」，弹出投票弹窗（猜明教还是六大派赢）
3. 投票后，进入 3-2-1 倒计时，双方各一句嘲讽弹幕
4. 若自动模式为「全自动」，自动选 Buff、自动投票、跳过倒计时

**状态**：`IDLE` → `RUNNING`

---

## 四、回合循环（每回合）

### 4.1 回合开始

1. 引擎执行回合初始化：
   - 快乐回血（宋青书→周芷若）
   - 玄冥神掌中毒扣血
   - 清除死拒马
   - 生成新拒马（如有巨马阵 Buff）
   - 性奋激活（宋青书+周芷若在场）
   - 小昭妹蛛变（随机变换职业）
   - 苦练加成（宋青书无周芷若时）
   - 概率连击抽选
   - 圣火令行列生成
   - 清空事件总线，重新注册所有监听器
2. 计算 Buff 加成，应用到每个单位的攻防血
3. 引擎产出回合开始数据包 `{ log, events, ally, enemy }`
4. 播放器播放回合开始日志，更新 Buff 图标
5. **血量在此时同步一次**（回合级数据，可接受）

### 4.2 行动轮询

1. 引擎按阵营交替选择未行动单位
2. 优先级：苦练宋青书 > 按站位顺序
3. 跳过：已行动、眩晕、飞天中、附身中
4. 被遮挡的近战单位：休息回血，计入 `attack-group`
5. 拒马：休息回血，计入 `attack-group`
6. 可行动单位：调用 `processUnitAttack`

### 4.3 单次攻击

引擎侧：
1. 选择目标（前排优先/残血优先/叛逆突袭特殊选）
2. 未命中判定（远程 3%、飞行 6%、其他 1%）
3. 闪避判定（飞行 15%、流云身法 25%、韦一笑残血）
4. 伤害计算（基础公式 + 破防 + 霹雳劲 + 叛逆真伤 + 鹿角杖法）
5. **伤害应用**：修改目标 `hp`，发射 `hp-change` 事件到 `GlobalStore`
6. 战士斩杀检查、圣火令掉落检查、拒马反伤
7. 闪避反击处理
8. 发射攻击后信号（触发白骨爪连锁、玄冥联动、性奋额外攻击）
9. 引擎产出攻击步骤数据包 `{ log, events, ally, enemy }`

播放器侧（标准播放节奏）：
1. **战斗文本行**：攻击者亮蓝光，防御者亮黄光
2. 远程飞箭/近战飞撞/图标攻击动画
3. **波动计算行**：波动数值 + 技能说明
4. **掉血弹幕**：波动行末尾弹出伤害数字
5. **战斗伤害行**：显示最终伤害，**血条同步更新**
6. 死亡特效（如目标死亡）
7. 白骨爪每次命中逐发更新血量，打完上死亡特效
8. 回血弹幕在攻击结束后显示

### 4.4 步骤结束

1. 引擎：`finalizeDeaths`，检查张无忌变身
2. 引擎产出步骤数据包
3. 播放器消费数据包，更新 UI
4. 检查胜负：一方全灭 → 进入战斗结束

### 4.5 海克斯选择

1. 每 3 回合触发一次（第 3、6、9…回合结束后）
2. 弹出选择窗口，3 选 1 或 Bug 模式下全选
3. 选择后应用 Buff，持续 4 回合
4. 小昭妹永久海克斯备份（团队 Buff 过期后单独续上）
5. 全自动模式随机选择

---

## 五、战斗结束

1. 一方全灭或达到 35 回合上限 → 战斗结束
2. 播放器：
   - 播放回合结束日志
   - 播放胜利特效（粒子、横幅、弹幕）
   - 圣火令掉落统计
   - 投票积分结算
   - 弹出战报窗口（输出/承伤/治疗/存活统计）
3. 状态：`RUNNING` → `GAMEOVER`

---

## 六、战后循环

1. 玩家可执行以下操作：
   - **下一关**：`currentStage + 1`，重新生成阵容，回到步骤二
   - **重新挑战**：当前关卡不变，重新生成阵容，回到步骤二
   - **选关**：跳转到指定关卡，回到步骤二
   - **重新开始**：回到第 1 关，清空所有 Buff，回到步骤二
2. 全自动模式：自动点击「下一关」，直到第 6 关通关后回到第 1 关
3. 圣火令在游戏中持久累积（localStorage），可在商店消费

---

## 七、数据流向规范

### 允许的通道（唯一主通道）

```
引擎 createRoundStepper → yield { log, events, ally, enemy } → 播放器 playBattle → 按节奏更新 UI
```

### 不允许的通道

- 引擎直接调用 `store.dispatch` 修改 UI 血量
- 引擎通过 `window._emitEvent` 绕过播放器
- 播放器通过 `store.subscribe` 被动同步引擎 state 来驱动攻击期间的 UI 变化

### 例外（可接受的非主通道）

| 例外 | 原因 | 控制方式 |
|------|------|----------|
| 回合初始化 `hp-change` | Buff 结算在攻击前，时机可预期 | 播放器在回合开始阶段统一处理 |
| 休息回血 `hp-change` | 独立时间点，不干扰攻击节奏 | 紧随 `attack-group` 日志 |
| 小昭姐衍生技 | 事件总线 `allyDamaged` 触发 | 作为攻击后事件，随步骤产出 |
| 回合级事件（回合开始/结束） | 非攻击事件，不影响血量节奏 | 直接 dispatch |

---

## 八、检查清单

每次架构改动后，对照以下条目：

- [ ] 引擎计算和 UI 更新是否只通过 `yield` 一条通道？
- [ ] 有没有任何地方直接调 `store.dispatch` 改血量？
- [ ] `window._emitEvent` 是否已被移除或仅入队 `GlobalStore`？
- [ ] 播放器的血量变化时机是否符合攻击播放节奏？
- [ ] 阵容生成、Buff 选择、战后循环是否完整闭环？
- [ ] 全自动模式是否能从第 1 关连续打到第 6 关并循环？
