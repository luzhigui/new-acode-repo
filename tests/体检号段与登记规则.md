## 四、121 / 123 / 124 登记规则

### 4.1 写权限

| 文件 | 作用 | 谁能写 | 域会话怎么做 |
|---|---|---|---|
| `121health-monitor.js` | `import` + `allRules`（浏览器侧执行面） | **只框架会话** | 提交登记申请 |
| `123static-scan.js` | `SCAN_FILES`（静态快检射程） | **只框架会话** | 提交登记申请 |
| `124rule-recipes.js` | `RULE_META`（规则配方/分组/强制开关） | **只框架会话** | 提交登记申请（含 tag/force） |
| `_registry/rule-domains.json` | 文件名 → 域（号段归属） | **只框架会话** | 申请里写清域名 |
| 自己的规则文件 | 规则本体 | **本域会话** | 直接写 |

**一条硬规矩**：域会话把文件建好后，**不许自己动 121/123/124**；由框架会话统一登记。否则就是本轮「8 个文件漏登」重演。

### 4.2 登记的载体文件（各域之间唯一的通信方式）

各域会话之间不能直接发消息，所以「登记申请」一律落到固定文件：

- **路径**：`tests/_registry/requests/D<N>.json`（**一个域一个文件**，共 9 个，已建好空壳）。
- **谁能写**：只有该域会话能改自己的 `D<N>.json`；框架会话合入后往同一文件回填 `state / mergedAt / mergedSha / note`。
- **不许做的事**：不许建临时申请文件、不许往别人的 `D<N>.json` 里写、不许直接改 121/123/124。
- **一个域多条申请**：往 `entries` 数组里追加，不改已有条目（合入状态由框架回填）。

```json
{
  "domain": "D5",
  "updatedAt": "2026-11-08 18:45",
  "updatedBy": "D5 会话",
  "entries": [
    {
      "slot": 253,
      "file": "253-zhou-dian-crazy-chain.js",
      "exportName": "rule253",
      "ruleName": "周颠癫传染链一致性(回归)",
      "ready": {
        "ruleFile": true,
        "caseFile": true,
        "recipeTag": true,
        "evidence": false
      },
      "recipe": { "tag": "hero:周颠", "force": "forceZhouDian", "note": "未出场即 skip" },
      "evidence": "定向用例 6 次命中 / 回放 120 场触发 4 场",
      "state": "draft",
      "note": ""
    }
  ]
}
```

**四项「已备」的含义**（域会话自己填 true/false）：

| 项 | 含义 |
|---|---|
| `ruleFile` | 规则文件已落盘在 `tests/health-rules/<号>-*.js`，导出名 = `rule<号>` |
| `caseFile` | 定向用例/负向样本已落盘（`tests/d<N>-*-case.mjs` 或等价），正反两向都验过 |
| `recipeTag` | 124 需要的配方已想好（`tag` 必填，`force`/`note` 可选） |
| `evidence` | 有触发证据（回放 N 场或定向用例命中数）；没有就填 false，并说明原因 |

**状态机**：`draft`（未齐，别催）→ `pending`（`ruleFile + caseFile + recipeTag` 三项为 true，等框架合入）→ `merged`（框架已合，回填 `mergedAt / mergedSha`）→ `needs-fix`（框架退回，`note` 写原因）。
`evidence=false` 不阻塞合入，但会进覆盖总账的「样本缺口」。

### 4.3 框架会话登记四件套（缺一不可）

1. `121`：`import { rule253 } from './health-rules/253-...js'` **且** 把 `rule253` 加进 `allRules` 数组。
2. `123`：`SCAN_FILES` 加 `'./health-rules/253-...js'`。
3. `124`：`RULE_META` 加 `'规则名': { tag, force?, note? }`（key 必须与规则文件里的 `name` 逐字一致）。
4. `_registry/rule-domains.json`：加 `"253-...js": "D5"`。

有撞名时：121 用纯数字别名（`import { rule179 as rule184 }`），数组写别名 `rule184`。

### 4.4 号段认领五步（防再撞）

1. 跑 `node tests/coverage-ledger.mjs`，看本域新段「剩余」和全局 `nextFree`。
2. 先在 `_registry/rule-domains.json` 登记「文件名 → 域」（**先登记后建文件**，这是唯一的占号动作）。
3. 文件编号取本域号段内最小空闲号；导出名 = `rule<文件号>`。
4. 建规则文件 + 定向用例；发登记申请。
5. 验收：`node tests/registration-check.mjs` 退 0，`node tests/coverage-ledger.mjs` 无「号段越界」。
6. 号段用完：向框架会话申请追加，由框架改 `domains.json` 的 `slots`，域会话不改。

### 4.5 冻结区例外

只有一类例外：**已经在途、编号落在 173–228 的文件**（如 181/182/183、227/228）允许按现状登记，不改号。
除此之外，任何新文件落进 123–228 都会被 `coverage-ledger` 报「号段越界」（229 起才校验）——看到即退回重编号。

### 4.6 框架会话多久合入一次

| 节奏 | 动作 |
|---|---|
| **每轮开工第一件事** | 扫 `tests/_registry/requests/D1..D9.json`，把 `state=pending` 的条目挑出来 |
| **每批（通常 1–3 条）** | 按 4.3 四件套登记 → 跑五节三条验收命令 → 一次 commit 推 main |
| **同一域连续多条** | 合成一批一起合，不做逐条小提交（减少推 main 次数） |
| **阻塞项** | 只有一条：四件套里 `ruleFile` 未落盘（文件不在 `tests/health-rules/`）——直接把该条置 `needs-fix` 并写 `note`，不等 |

合完回填：`state="merged"`、`mergedAt="YYYY-MM-DD HH:mm"`、`mergedSha=<commit 短 sha>`；退回回填 `state="needs-fix"` + `note` 写原因（如「导出名不是 rule<号>」「规则名与 124 key 不逐字一致」）。

### 4.7 合入时怎么处理冲突

| 冲突类型 | 判定 | 处置 |
|---|---|---|
| **同一号段两人申请** | 两个 `D<N>.json` 或同一 `D<N>.json` 里 `slot` 重复 | 先到先得：先合入的保留原号；后到的置 `needs-fix`，`note` 写「号 253 已被 D5 占用，请改用 254」，由域会话改文件名+导出名后重新申请 |
| **文件名不同、导出名同号** | 如 `177-*.js` 与 `179-*.js` 都导出 `rule179` | 不动原文件；121 用纯数字别名（`import { rule179 as rule184 }`），数组写别名。**禁止英文别名**（registration-check 只认 `rule\d+`） |
| **规则名撞车（124 key 重复）** | 两条规则 `name` 逐字相同 | 后申请的那条置 `needs-fix`，要求改名（在名字后加「·第二批」等区分词），不改已合入那条 |
| **公共表被别人直改** | 发现 121/123/124 出现非框架会话的提交 | 不回滚、不争吵：以磁盘现状为准补齐缺失登记，把该条申请标 `merged`，并在本文件五节记录一笔；重复发生则按第二节第 3 条冻结该域直接改表的权限 |
| **git 推送被拒 / 双方都改了同一行** | `push` non-fast-forward 或 merge 冲突 | 只由框架会话收口：`fetch` → `merge origin/main` → 冲突按「两边内容都保留、按轮次排序」解 → 跑验收 → 一次 push；域会话不抢推 |
