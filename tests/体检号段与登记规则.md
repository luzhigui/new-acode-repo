## 四、121 / 123 / 124 登记规则

### 4.1 写权限

| 文件 | 作用 | 谁能写 | 域会话怎么做 |
|---|---|---|---|
| `121health-monitor.js` | `import` + `allRules`（浏览器侧执行面） | **只框架会话** | 提交登记申请 |
| `123static-scan.js` | `SCAN_FILES`（静态快检射程） | **只框架会话** | 提交登记申请 |
| `124rule-recipes.js` | `RULE_META`（规则配方/分组/强制开关） | **只框架会话** | 提交登记申请（含 tag/force） |
| `_registry/rule-domains.json` | 文件名 → 域（号段归属） | **只框架会话** | 申请里写清域名 |
| 自己的规则文件 | 规则本体 | **本域会话** | 直接写 |

**一条硬规矩**：域会话把文件建好后，**不许自己动 121/123/124**；由框架会话统一登记。否则就是本轮「8 个文件漏登」重演。

### 4.2 登记申请格式（域会话 → 框架会话）

保存为 `tests/_registry/requests/<域>-<文件名>.json`（只增不改；框架会话合并后保留原文件作审计痕迹）：

```json
{
  "domain": "D5",
  "file": "253-zhou-dian-crazy-chain.js",
  "exportName": "rule253",
  "ruleName": "周颠癫传染链一致性(回归)",
  "recipe": { "tag": "hero:周颠", "note": "未出场即 skip" },
  "needScan": true,
  "evidence": "定向用例 X 次命中 / 回放 Y 场触发"
}
```

### 4.3 框架会话登记四件套（缺一不可）

1. `121`：`import { rule253 } from './health-rules/253-...js'` **且** 把 `rule253` 加进 `allRules` 数组。
2. `123`：`SCAN_FILES` 加 `'./health-rules/253-...js'`。
3. `124`：`RULE_META` 加 `'规则名': { tag, force?, note? }`（key 必须与规则文件里的 `name` 逐字一致）。
4. `_registry/rule-domains.json`：加 `"253-...js": "D5"`。

有撞名时：121 用纯数字别名（`import { rule179 as rule184 }`），数组写别名 `rule184`。

### 4.4 号段认领五步（防再撞）

1. 跑 `node tests/coverage-ledger.mjs`，看本域新段「剩余」和全局 `nextFree`。
2. 先在 `_registry/rule-domains.json` 登记「文件名 → 域」（**先登记后建文件**，这是唯一的占号动作）。
3. 文件编号取本域号段内最小空闲号；导出名 = `rule<文件号>`。
4. 建规则文件 + 定向用例；发登记申请。
5. 验收：`node tests/registration-check.mjs` 退 0，`node tests/coverage-ledger.mjs` 无「号段越界」。
6. 号段用完：向框架会话申请追加，由框架改 `domains.json` 的 `slots`，域会话不改。

### 4.5 冻结区例外

只有一类例外：**已经在途、编号落在 173–228 的文件**（如 181/182/183、227/228）允许按现状登记，不改号。
除此之外，任何新文件落进 123–228 都会被 `coverage-ledger` 报「号段越界」（229 起才校验）——看到即退回重编号。
