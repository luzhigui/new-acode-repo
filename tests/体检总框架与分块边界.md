## 一、现状：体检体系是六层结构

| 层 | 代表件 | 本轮实测 | 判定口径 |
|---|---|---|---|
| ① 静态结构层 | `123static-scan.js`、`layer-direction-scan.mjs`、`contract-consistency.mjs`、`health-rules-syntax-sweep.mjs` | 全绿 | 不跑游戏，只读源码文本 |
| ② 文本规则层 | `tests/health-rules/*.js` | **68 个文件**（origin/main 65 + 在途 3）；121/123/124 已补齐登记（`registration-check` 绿） | 只读渲染后战报条目（type+text） |
| ③ 数值真值层 | `stat-decl-vs-actual-check.mjs` | **57 条契约**（旧文档写 49/58，均已过期）；`--scan-groups` 是手动命令 | 逐步比对「声明值 vs 账本实际值」 |
| ④ 变异牙齿层 | `mutation-teeth.mjs` | **48 个变异条目**（A/T）；全量重跑约 20–40 分钟，默认不跑 | 故意改错代码，证明规则非恒绿 |
| ⑤ 基线/金样/大样本 | `140-baseline.js`、`translate-golden.mjs`、`fuzz-invariants.mjs`、`smoke-headless.mjs` | 18 场 / 35 场 / 2100 场 / 20 局 | 行为 diff、字节 diff、随机扫射 |
| ⑥ 编排与自证 | `run-all.mjs` | **25 项计退码 + 31 项观察项**（手写清单） | 串行跑齐、出一页汇总 |
| 附属 | `manifest.json`（PWA 离线预装清单，由 `tools/830` 生成） | 155 个文件 | 与体检判据无关，只是被 `manifest-fresh-selftest` 顺带看守 |

**结论：层与层分工清楚，问题不在“缺工具”，而在「覆盖账本」和「并行扩容方式」。**

## 四、结构级问题（按严重度）

### P0（会让覆盖静默失效）

1. **四份手写登记表 + 两份手写清单**
   - 规则要同时登记：`121health-monitor.js`（import + allRules 数组）、`123static-scan.js`（SCAN_FILES）、`124rule-recipes.js`（RULE_META）、`tools/806`（复制包，意外）。
   - 编排要同时维护：`run-all.mjs` 的 CHECKS（25）与 OBSERVES（31）。
   - 现状靠 `registration-check` / `run-all-integrity-selftest` / `orphan-selftest-sweep` 事后兜；**漏登本身仍是静默事件**（要么不执行、要么从不进汇总）。
2. **共享大文件是并行冲突源**
   - `stat-decl-vs-actual-check.mjs`（58 条契约同一张 CONTRACTS 表）、`mutation-teeth.mjs`（48 条同一张表）、`124 RULE_META`、`121 allRules`、`run-all` 清单。
   - 9 个会话若都直接改这些文件，必然互相顶掉；历史上已发生「契约被旧版顶掉」「锚点静默失效」两次覆盖事故。
3. **覆盖度只有“样本触发率”，没有“机制清单 vs 规则清单”的双向账本**
   - `coverage-report` 只能看见“样本里出现过的机制”；从未在 20×7 样本出现的机制根本不进账本，会假报“0 未覆盖”。
   - 静态对账（`--scan-groups`）是手动命令，不常驻、不自动报警。
4. **规则号与文件名号双轨，且号段有洞/撞号**
   - 文件名 123–172 ↔ 规则 id rule70–rule172；缺 rule103、rule114–155 大段空档、rule156 跳号、rule170–172 跳号。
   - `140-baseline.js`（runner）与 `health-rules/140-wei-dodge-cloud.js`（规则）同号，属已知历史债。
   - 后果：新人/新会话无法从编号推出归属，也没法按号段分配所有权。

### P1（会拖慢但不会静默失真）

5. **观察项只进不出**：31 项 OBSERVES 长期挂在“待拍板”，没有升降级节奏，红项容易变成背景噪声。
6. **文档口径过期**：`体检蓝图` 写 49 契约 / 46 牙、`使用说明` 写 45 条规则，实测 58 / 48 / 47；同一状态散落在蓝图、使用说明、迭代日志、牙口矩阵、fact 矩阵五处。
7. **manifest.json 概念混入体检**：它是 PWA 离线预装清单，不是体检登记簿，却挂在 OBSERVES 里，容易被误解成“体检清单”。

## 六、公共层改造建议（框架会话落地）

按“先止血、再自动、后收口”三步：

1. **止血（本轮之后立刻做）**
   - 新建 `tests/registry/` 单一真源：`rules.json`（规则文件↔规则id↔域↔名称）、`suites.json`（CHECKS/OBSERVES↔脚本↔hard/tier）、`contracts.json`（契约 id↔域↔绑定键）、`mutations.json`（变异 id↔域↔目标）。
   - 现有四份手写登记改为**从 registry 生成或校验**：`registration-check` 增加“registry ↔ 磁盘 ↔ 121/123/124”四向 diff；`run-all` 清单由 `suites.json` 驱动。
   - 目的：并行会话只改自己那几行 JSON，不再改 5 个大文件。

2. **自动（覆盖账本）**
   - 把 `--scan-groups` 从手动命令变成常驻项：`stat-decl` 输出未覆盖 group 清单，非空即黄标；新增 `coverage-ledger.mjs` 汇总「引擎机制清单（静态抽取）↔ 规则 ↔ 契约 ↔ 变异 ↔ 样本触发」五列，输出缺口表。
   - `coverage-report` 保留“触发率”，新增“机制级覆盖”（不是规则级）。
   - 目的：消除“样本没出现 ⇒ 看不见 ⇒ 假报 0 未覆盖”。

3. **收口（报告统一）**
   - `run-all` 汇总页改为三段：**红线（计退码）/ 观察项（分 hard 与研判）/ 覆盖缺口（新增）**。
   - 新增一份机器可读产物 `tests/.report/health-summary.json`（谁绿谁红、缺口、域归属），供 9 个会话各自读自己的 section，避免抢同一份报告。
   - 文档收敛：本文件为“结构与分块唯一源”，`体检蓝图` 降为“阶段路线”，`使用说明` 只留命令与坑，数字一律不写死（改为“跑命令看”）。

## 七、并行协作协议（9 会话不打架）

### 7.1 写权限

- 域会话**只写**：自己号段的 `health-rules/*.js`、`tests/dN-*-case.mjs`、`tests/baselines/dN-*`、`tests/_registry/fragments/dN.json`。
- 域会话**只读**：公共层一切文件、其他域文件。
- 框架会话**只写**：公共层 + 本文件 + `tests/_registry/*` 汇总。
- 主代码（`core/ modules/ render/ player/ ui/ infra/ fx/ content/ tools/`）**任何人都不写**；需要改的写成需求清单。

### 7.2 登记申请格式（域会话 → 框架会话）

```json
{
  "domain": "D5",
  "kind": "rule",
  "file": "tests/health-rules/197-d5-zhou-dian-crazy.js",
  "ruleId": "rule197",
  "name": "周颠癫狂触发(回归)",
```
