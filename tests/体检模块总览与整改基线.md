1. **做「新增判据」之前，先确认它盯的字段在主代码真的存在**：打开 emit 点（`core/209` / `render/40x` / `modules/33x`）逐字看这个 fact 的 `data` 到底带哪些键；`immuneFact.target` 只带 `uid/name/camp` 这种"精简快照"是常态，**不许按完整单位结构假设**。
2. **做「数值对账」之前，先确认真值只有一处**：比例/阈值必须 `import` 内容表或 `CONFIG`/枚举，**不许在规则里抄常量**（229 抄 `'ALLY'` 而 `CAMP_TYPES.ALLY === 'ally'` 就是这么错的）。
3. **做「逐条判定」之前，先确认这条判据对哪些"辅助组/容器组"天然不成立**：免疫/破防/护盾/回合符这类组只是条目容器，要先把 `judgeGroup` 这类范围收窄条件写出来，再判。
4. **做「口径换算」之前，先确认引擎用的是实数还是印数**：显示取整（`fmtNum`/`fmtHpText`）与账本实数分开判，容差写 `1e-6`，**不许 floor/round 之后再比**。

### 写规则时

5. **做「返回」之前，先确认形状只允许三种**：`'pass'` / `'skip'` / `{fail:boolean, msg, observe?}`。**任何返回普通字符串都算红**（`rules-replay` 与 `121` 都已按此判，别再写 `fails.join('；')`）。
6. **做「零触发」分支之前，先确认它返回 `'skip'` 而不是 pass**：没场景 ≠ 通过；`dead` 统计会把恒 skip 单独列出，别用 pass 掩盖。
7. **做「观测态」之前，先确认它有升级日期**：`observe` 只能用于「实测拟合、非引擎真值」且必须在文件头写「升级条件」（例如误报归零 N 场后转硬判）。当前 6 条观测态全部缺升级条件，**新规则不许再新增无条件的 observe**。
8. **做「可红证明」之前，先确认有反向样本**：每条硬判据必须在定向用例里能被人为弄红（改坏输入 → `fail:true`），没有反向样本 = 没牙 = 不收。
9. **做「注释/版本」之前，先确认 `export const VER` 与头注释同时改**：`ver-drift-selftest` 会扫主代码七目录 + tests，两处不一致会被绊线咬住。

### 落盘与登记

10. **建文件之前，先确认号已登记**：先写 `_registry/requests/D<N>.json`（slot + 文件名 + 导出名 `rule<号>` + 规则名），由框架面分配；**不许自行改名占号**（273/274 写错号、313/314 假条目都是这么来的）。
11. **改 121/123/124 之前，先确认自己是框架面**：域会话一律只写申请 + 自己号段文件；`registration-check` 必须 **退 0** 才算本轮收口（当前不退 0，是欠账不是"预期"）。
12. **登记 124 之前，先确认 key 与规则 `name` 逐字相同**：改名必须同步改 key（`db0aec1a` 就是漏了这一步）。
13. **加 run-all 条目之前，先确认同名条目不存在**：同一项重复登记会被 `run-all-integrity-selftest` 抓，但上游漂移后仍会漏删。
14. **改公共文件之前，先确认这次不改「覆盖分母」**：121 import 数与磁盘规则数必须相等（146 vs 161 的差就是硬伤）；做不到相等就在申请里写清"哪几条只走回放"。

### 验证与收口
