# 变异牙齿全量刷新·操作单

> 看板 #53 的交付件（2026-11-21）。纯文档：不改任何判据/阈值/基线/主代码。
> 工具本体：`tests/mutation-teeth.mjs`（V2.9.37）；产物：牙口矩阵 `tests/牙口矩阵.md`。

## 0. 什么时候需要刷新

判据文件（`tests/health-rules/*.js`）、规则宿主（`tests/122health-utils.js`）、被测主代码
（`core` / `modules` / `infra` / `player` / `render` / `content`）、或变异表本身**任一改动**，
`tests/.mut/teeth-results.txt` 就配不上当前代码了。此时 `tests/牙口矩阵.md` 顶上写的
「某条规则有牙」结论**不能当依据**——这就是看板 #43 那次「落后 19 笔提交」的病根。
`--report` 有新鲜度守卫会硬拦，但守卫只在**你跑它的那棵树里**自比，跨树/跨基线的漂移它看不见
⇒ 跑批前后的基线核对是本操作单的第 5 步。

## 1. 前置条件

| 条件 | 为什么 | 怎么满足 |
|---|---|---|
| **干净 detached worktree** | 主树常有并行会话的 WIP；脏树会被脏树守卫判「结论作废」并退码 | `git worktree add --detach D:/_hc_xxx <基线commit>`，跑前 `git status --porcelain` 必须为空 |
| worktree 里改过脚本要先 commit | 改动没提交 = 树是脏的 = 守卫拦下 | 改完先 `git commit`，再跑 |
| **Git Bash 用全路径** | 本机 `bash` 不在 PATH | `D:\Git\bin\bash.exe -lc '…'`（命令用 PowerShell **单引号**包裹，否则 `$?` 被提前展开成 True/False） |
| 落盘别用 PowerShell `>` | 它写成 UTF-16，生成的 `.sh` 整片作废 | 用 node `fs.writeFileSync` 落盘，或在 Git Bash 里重定向 |
| `node_modules` | 规则回放不需要；但 `d12v2-scan-case` 需要 `acorn` | 需要时用目录联接指回主仓：`cmd /c mklink /J D:\_hc_xxx\node_modules "<主仓>\node_modules"` |

## 2. 四步固定跑法

```bash
# ① 先验锚点：48 条变异的 from 串是否还在（锚点失效 ⇒ 变异静默不生效 ⇒ 渲成「规则没牙」的假绿）
node tests/mutation-teeth.mjs --verify
#    期望：「✅ 48 条变异锚点全部有效」+ 自证①~⑤全过；EXIT=0

# ② 重建 48 棵基树（HEAD 快照 + 逐棵注入变异）
node tests/mutation-teeth.mjs --emit-prep > tests/.mut/prep.sh && bash tests/.mut/prep.sh
#    产物：tests/.mut/_base + tests/.mut/m-A1 … m-A30 / m-T1 … m-T18

# ③ 跑 49 棵树（_base + 48 颗牙），每棵四件套：
#    rules-replay → 140-baseline --check → stat-decl-vs-actual-check → 同上 --fingerprint
node tests/mutation-teeth.mjs --emit-run > tests/.mut/run.sh && bash tests/.mut/run.sh
#    产物：tests/.mut/teeth-results.txt（每棵以「##### MUT <id> #####」开头，末尾「ALL DONE」）

# ④ 出结论 + 重出矩阵正表
node tests/mutation-teeth.mjs --report --matrix-out=tests/牙口矩阵.md
#    期望：「💾 牙口矩阵已落盘：tests/牙口矩阵.md（48 行）」EXIT=0
```

> ⚠ **第 ④ 步会把矩阵写进 worktree ⇒ 下一次跑就被脏树守卫拦下**（退码 3「结论作废（环境不干净）」）。
> 跑完先 `git checkout -- tests/牙口矩阵.md` 还原，再跑下一次。退出码 1 与 3 分家是对的：
> 1 = 结果真陈旧（指纹/覆盖/树 mtime 对不上），3 = 环境不洁，不能当成代码缺陷。

## 3. 并行分片跑法（串行会超时）

实测耗时（同一台 6 核机、机器同时有别的会话在跑）：

| 跑法 | 耗时 | 出处 |
|---|---|---|
| 串行 49 棵 | ≈2h42m（单棵 ≈3.3min） | 本仓库第190轮实测 |
| 串行 49 棵 | 1h19m | 夜间第251轮实测 |
| **4 分片并行** | **≈30min** | 本仓库第190轮实测（各片 12~13 棵） |
| 6 路并行 | ≈18min | 夜间第251轮实测 |

分片做法：**把 `run.sh` 复制成 K 份，只改 `OUT` 文件名与 `for id` 列表**，每棵树的三件套命令
逐字不变（只改调度、不改口径）。仓库里**没有**现成的分片脚本，这一步是手工做的：

```bash
cd tests/.mut
# ① 看 run.sh 的结构：头部有 OUT 文件名，主体是 for id in <49 个 id> … done
# ② 复制 K 份，每份改两处：
#      OUT=<各自的结果文件名>            （分片之间不许写同一个文件）
#      for id in <本片负责的 id 列表>     （49 个 id 平均切 K 段，A 类/T 类混排，别按类别切）
# ③ 并行跑（每片一个后台进程），全部结束后再拼装
for k in 1 2 3 4; do bash tests/.mut/run-shard$k.sh & done; wait
```

跑完把各片**按 id 拼回** `tests/.mut/teeth-results.txt` 再 `--report`。

> ★ **拼装的坑（真踩过）**：`[...meta, ...blocksJoined, 'ALL DONE'].join('\n')` 里的
> `...blocksJoined` 会把**字符串逐字符展开**成数组元素 ⇒ 整个结果文件整片逐字符换行（127 万行），
> `--report` 报「结果覆盖不全（49 条缺结果块）」。正确写法：`join` 完之后**当单个数组元素**放进去，
> 不加 `...`。
> 另：拼装器只做「块搬运 + 排序」，不改任何内容；`#META` 头按 key 去重（4 片内容一样，只有 AT 时间戳不同）。

## 4. 判定口径速查（八类 + 两条恒等式）

矩阵正表八类判定：锚点失效 / fact 文本有牙 / 真盲区(装饰品) / 对照器兜住 / 仅基线兜底 /
待确认盲区 / 未观测到影响 / **对照器恒空转·不作证**。

两条恒等式（改判据前先对着它们想一遍，别拿"血条净差"当"本次伤害扣了多少血"）：

1. **印数恒等式**：`印数 === 引擎扣血 + 护盾吸收`。
   推导自 `render/407` L98 `shownDmg = max(0, dmg − hpBonus − cappedLoss)`——
   上限在**两边同扣**，公式里不能再加一次；护盾吸收**不在**印数里、只在引擎账里。
   （第191轮实测：按此恒等式对账，规则 303 的 107 条红降到 0。）
2. **护盾余额语义**：`dmgResult` 只带**剩余**余额（`_shield` / `_shieldExtra` / `_permShield`），
   **不带本击吸收了多少**（`shieldAbsorbed` 只写进 `target.state`）⇒ 想对账得让主代码把数带出来。

## 5. 起跑后的基线漂移核对（共享工作树专属坑）

本仓是共享工作树，体检期间别的会话会持续推 main。**固定基线跑完一定会漂**，
所以跑批结束前做一次漂移量：

```bash
git diff --name-only <跑批基线commit>..main -- core modules infra player render content tests/health-rules tests/122health-utils.js
git log --oneline <跑批基线commit>..main
```

- 上面的文件列表**为空** ⇒ 结论仍配得上最新 main，直接用；
- **非空** ⇒ 指纹已变、结论对最新 main 失效。两条路：① 等仓库安静时按本单重跑；
  ② 把差异逐条登记成看板任务（写清基线 commit、漂移文件、可能受影响的判定域），
  **不要**把「差一点点」当成还能用——牙口矩阵顶上写的就是结论本身。

## 6. 常见报错对照

| 现象 | 原因 | 处置 |
|---|---|---|
| `--report` 退 1 +「结果覆盖不全（N 条缺结果块）」 | 结果文件被逐字符写坏（见第 3 节的坑） | 重拼装，别手改结果文件 |
| `--report` 退 1 +「指纹不符」 | 结果与当前代码不同源 | 按第 2 节四步重跑，**不要** `--allow-stale` |
| `--report` 退 3 +「结论作废（环境不干净）」 | 矩阵/脚本改动没提交 ⇒ 树脏 | 先 `git checkout --` 还原或提交，再跑 |
| 回放脚本输出「脏树警告…恒空转/假绿/覆盖不足结论作废」 | 在脏树上跑 | 换干净 detached worktree |
| `prep.sh` 跑出来全是乱码 / 语法错 | PowerShell `>` 写成 UTF-16 | 换 Git Bash 或 node 落盘 |
| 某棵树「锚点失效·结论作废」 | 主代码改写了变异的 from 串 | 更新 `mutation-teeth.mjs` 的 `MUTATIONS`，或判该牙作废并登记 |

## 7. 收尾

- 矩阵正表**有变更** ⇒ 必须在 `tests/体检迭代日志.md` 履历登记（基线非调节阀：旧结论不作数，
  但"为什么变"要留痕），并在看板对应任务行写明结论行与退出码；
- `--report` 只出结论，不重录基线：`140-baseline` 只跑 `--check`，**永远不要**为了让它变绿去 `--update`；
- 跑完把 worktree 删掉：`git worktree remove <路径>`（临时树里的探针提交从未推 main，留着只会误导下轮）。
