# 光明顶 5v5 共享体检跑法

> **跨软件通用入口**：本 skill 是深度跑法手册。若你是别的软件/别的会话的 Agent、且想一句话拿到"怎么认领任务 + 怎么跑"，先读仓库根 `AGENTS.md`——那里有一份可整段复制粘贴到任意聊天的自包含提示词（中英双语），读完无需上下文即可独立干活。

## 0. 为什么有这个 skill
体检慢、且容易"各跑各的、重复劳动、漏掉别人发现的问题"。本 skill 把跑法凝成两份东西：
- **共享看板** `tests/_registry/HEALTH_BOARD.md`：所有人跑前先看，认领最小编号 open 任务，做完回填，永远留 ≥3 个开放任务。
- **本跑法**：三种入口 + 并发提速，统一命令与红线。

## 1. 共享看板协议（核心，动手前必读）
看板格式与字段见 `references/board-template.md`。纪律：

1. **动手前先 `git fetch`**，再读看板；确认没有叠着别人的 `doing`（避免两人占同一格还互相覆盖）。
2. **认领**：有 `open` 任务 → 把**最小编号**那条改成 `doing`，写 `owner`（你的标识：会话名/agent 名/人名）+ `更新时间`。
   **认领后立刻 `git add tests/_registry/HEALTH_BOARD.md && git commit -- tests/_registry/HEALTH_BOARD.md -m "…" && git push`**（path-limited，绝不 `-A`）。
   ⚠️ 只 stage 不 commit 是坑：共享树里另一个 Agent 提交看板时会把你未提交的改动一起带走，归属和时间戳全会乱。
3. **无 open 任务** → 自己往看板补 `1/2/3` 至少三条（标题 + **可核查的验收标准**），再领 #1。**加任务前先确认它没被既有设计作废**（例：某脚本已主动降级成"候选生成器、只报不判红"，就不要再加"补会变红的断言"——那与有意设计冲突，是过时任务）。
4. **做完**：你的任务标 `done`，并**确保看板永远 ≥3 个 open**——不够就补新任务（做1留234、做2留345、做3留456）。**`done` 行必须含「实际命令 + 实际结论行（含 EXIT 码）」**，否则视为未完成（防"标 done 但没真跑/没真落地"）。
5. **看板改动单独 commit + 双推**（path-limited），让别人立刻看到，避免两人抢同一格。
6. **并发冲突**：靠"写自己名字+时间戳"占格；若 `git` 报冲突或 `git status` 发现混进别人的文件，**先 `git fetch` 重读看板、重领未被占的最小编号**，切勿 `git add -A` 强推。

> **主代码任务口径（红线延伸）**：真缺陷需要改主代码的，任务状态写 `doing`/`blocked` 并附**转交块**（START/END 标记的可复制最终代码）。贡献者**自己绝不落主代码**；只有当 zhong/授权方已把主代码提交进仓库、且你能附上"探针由红转绿"的实际证据时，才把该任务标 `done`（标的是"已记录落地"，不是"我落的地"）。owner 写你的会话名即可，git author 是操作人（统一为 luizhigui），二者不冲突。
> **★ 转交块与任务状态解耦（2026-11-14 立）**：只要在**报告里**说出「要主代码配合 / 需主代码落地 / 需主代码修复」，就必须在**同一轮回复里**贴出转交块——**与看板状态无关**（登记成 `open` 也算触发，不许靠改状态绕过）。详见 §4.5。写「只写转交块、等授权落地」却没贴块 = 开空头支票，视为本轮未完成。

## 1.5 环境铁律：共享主仓是**单工作树**，引擎回放在脏树上会失真/崩溃
D 盘 `new-acode-repo` 是多人/多会话**共享的一个工作树**。别的会话常会留未提交的主代码 WIP（ui/ core/ modules/ infra/ render/ 的 `MM` 暂存态）。后果：
- `rules-replay` / 任何依赖引擎回放的自检（`rule-idle-selftest`、`fact-coverage-selftest`、变异牙等）在脏树上会**崩溃（exit≠0 且零统计）**或被**动态失真**（规则被挤出样本、skip 数虚高）。
- 据此下"恒空转 / 假绿 / 覆盖不足"结论**不可信**。本会话就吃过亏：脏树上 205 规则 skip=156 被误判成恒空转，干净树复跑实得 pass=16。

**强制做法（任何依赖引擎回放的结论都必须遵守）**：
1. 先 `git fetch` 锁定远端**稳定 tip**（别用叠了 WIP 的本地 main）。
2. `git worktree add --detach D:/tmp_hc_<任务> <远端tip>` 建**干净 detached 工作树**，在里头跑。
3. 在干净树得到结论后，再回主树只 `git add` 你改的 `tests/` 文件、`commit -- <file>`、`push`。
4. 绝不在叠了 WIP 的主树直接下"恒空转/假绿"结论；若只能脏树跑，结论必须显式标注「脏树，待干净树复核」。

## 2. 体检怎么跑（三种入口）
### A. 浏览器整跑（最贴近真实，慢）
```
"<你的 python>" tools/health_auto_check.py 600 7 100
```
- 系统 Edge 驱动跑第 2–7 关，约 4 分钟；报告打印终端，异常 = `issues` 数组。
- 并发提速：分进程跑不同关段（如一人 `--stages 2-4`、另一人 `--stages 5-7`；若脚本不支持关段参数，就各跑全量不同 `SEEDS`）。资源开销大，按需。

### B. Node 守门全套（快，结构/契约/守门）
```
node tests/run-all.mjs              # 全量（含重型采样）
node tests/run-all.mjs --quick      # 跳过重型采样，更快
node tests/run-all.mjs --jobs 4     # 并发跑（默认 1=顺序），各脚本独立安全，明显提速
```
- 退码：`CHECKS` 任一红 → `exit 1`；`OBSERVES` 只显形、不计退码。
- `--jobs N`：用 `spawn` 异步池并发跑，输出按完成序打印、末尾汇总表仍按原顺序；默认 `1` 时行为与原顺序跑完全一致。

### C. 手动 / 手机端
打开 `tests/120test-runner.html` → 🏥 → 选模式。静态体检已拆成独立入口（不等 160 个规则模块），手机端也能即时响应。

命令速查见 `references/commands.md`。

## 3. 报告口径（避免误读"没报就是没问题"）
- 报告头写清 `coverage`：在册 / 执行 / 未触发 / 跳过率。**跳过率 ≥50% 直接标「⚠ 覆盖不足：本次结论不代表没有问题」**。
- 只报 `issues` 数 ≠ 代码干净；规则大面积 `skip` 时尤其要警惕——那叫"没查到"，不叫"没问题"。

## 4. 红线（动之前先看）
- **跨线融合不照搬完成状态（2026-11-14 立）**：本仓 `main` 与夜检 `nightly/第N轮` 曾长期分叉（见看板 #10）。夜间看板/日志里的 `done` **只在夜间分支代码上成立**。要把夜间成果融合进 main 时：只登记**缺陷线索**，逐条在 main 侧代码复核是否仍存在（例：夜间记「#12 已修复」，main `core/217` 的快照相减其实还在；夜间 #4 标 done，main 的 `fact-coverage-selftest.mjs` 并未跟着改），未落地前保持 `open`/`blocked`，**绝不把夜间的 done 抄成 main 的 done**——那是「看板说 done、代码没改」的假绿。同理，夜间 `open` 的缺陷也要先确认 main 侧没被白天改掉再登记。
- **主代码零触碰**：体检侧只改 `tests/` + 打包清单。发现主代码缺陷只写**转交块**，由人落地，不在体检会话里改主代码。
- **只 `git add` 具体文件**：绝不 `git add -A` / `git add .`，避免扫入并行会话的半成品（WIP/.tmp）。
- 不改阈值、不重录基线（`baselines/*.json` 非调节阀）、不放宽判据。
- 变异牙齿全量需走 `--emit-prep`→`prep.sh`→`--emit-run`→`run.sh`→`--report`；`_base` 陈旧会废锚点。
- 主代码任务标 `done` 仅是"记录已落地"，贡献者自己从不落主代码（见 §1 红线延伸）。
- **说要主代码配合 ⇒ 同轮必贴转交块**（见 §4.5），禁「只写转交块、等授权落地」这类无块空头话。

## 4.5 转交块：触发、规格、取证纪律（2026-11-14 立）
> 起因：某轮报告写「要不要主代码配合：要，但本轮一处没碰」，列了 3 条主代码缺陷却一个块都没发；
> skill 虽提过"附转交块"，但绑在任务状态上、也没规定"报告里说要配合时同轮就得贴"，遂被绕过。

**触发条件（任一命中即必须交块）**：报告/看板/结论里出现「要主代码配合 / 需主代码落地 / 需主代码修复 / 发现主代码缺陷 / 只写转交块」等表述。
**与状态解耦**：即使任务登记为 `open`（"信息融合"）也照样触发；不许用改状态、写"待补/后续/等授权"来拖到下一轮。

**合格转交块的规格（块 = 可复制、可直接落地）**：
1. 用 `【START 转交块：<文件>】` / `【END】` 包住，**块内只放最终代码**——改哪个函数就给**该函数的完整版本**（发代码前必须通读整个函数从头到尾，不许只贴改动的几行、不许 `// ...省略`）。原状/差异说明写在**块外**。
2. 块外必须写：① 落点文件与行号；② 根因一句话 + 证据（代码原文/实测结论行）；③ 最小修复说明；④ **验收命令 + 预期结论行**（含 EXIT 码）；⑤ 明确标注「本会话未落地主代码，由人落地」。
3. 一处改动 = 一组 before/after 对比；每轮 2–4 组，超了先问。
4. 依赖既有架构、命名、字段，**不新造通道**（例：回血账本已有 `recordHpAudit` + `_audit.hp` 分组先例，就别另起炉灶）。

**取证纪律（防编接口，血的教训）**：发块前必须把相关函数**整个读完**，确认被调用函数的**真实返回值/参数**。
反例：夜间 #12 验收标准写「回写值取 `applyStatChange` 的实际返回增量（该函数已有 `actualDelta`）」——实际 `core/214:299` 返回的是 `target.state._pendingDeath || false`（**死亡布尔**），`actualDelta` 只是 L270 的局部变量、从不 return。照抄就会写出调用不存在接口的假修复。

**分类处理（不是所有缺陷都发"修复块"）**：
| 情形 | 该交什么 |
|---|---|
| 根因确证、改法确定 | 可落地的**修复转交块**（START/END 完整代码 + 验收命令） |
| 诊断存疑 / 夜间结论与 main 现状不符 | **不发修复块**；交「复核探针脚本 + 判据」，并在看板标注「诊断存疑，待复现」，说明为何不发（防把没证实的缺陷当真去改） |
| 属**改判据 / 会改变结论 / 需拍板** | 交**方案 + 影响面清单**，明确标「待 zhong 拍板，未落地」，不伪装成已定稿代码 |

**看板登记口径**：这类任务的验收栏写「转交块已交付（轮次/日期）+ 主代码落地后复跑 X 由红转绿」，状态 `blocked`；**没交块不许把验收栏写成"已闭环"**。

## 5. 完成定义
- 任务有可验证结果（`done` 行含**实际命令 + 实际结论行（EXIT 码）**）。
- 依赖引擎回放的结论，必须**在干净 detached 工作树**得出（脏树结论不算数，见 §1.5）。
- **报告里凡声称"要主代码配合"，本轮回复必须含符合 §4.5 规格的转交块（或明确归类到"诊断存疑/待拍板"并给出对应交付物）；一块未交视为本轮未完成。**
- 看板已更新（领格 / 补格 / 标 `done`）。
- 改动只 `add` 具体文件，已 commit + 双推，两端 tip 一致。
